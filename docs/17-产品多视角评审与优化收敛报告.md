## 2. 产品现状客观画像（基于 v0.3.1 源码与文档核实）

### 2.1 真实能力与核心护城河

1. **只读图谱与多分支对比（不可替代优势）**：`crates/git-read` 基于 `gix` 纯只读实现增量图谱分页、稳定轨道（`crates/graph-layout`）、Base/Compare 双槽两点与三点对比、`merge_base` 定位、`change_origin` 撞车文件标识（`both`）、等价提交识别，以及收敛后的节点悬浮卡（`CommitHoverCard.tsx` 的 `included_in_head` 与本地/远程合并胶囊）。
2. **受限写门禁与内置终端协同**：`crates/git-write` 通过 `WriteKind` 白名单、写前 Gate、写互斥锁与参数数组执行安全隔离写操作；底部 `TerminalHost` 提供按仓库保活的 `lazygit` 与 `shell` PTY，退出后自动联动 `RefreshCoordinator` 刷新仓库。
3. **工程基础设施完备**：具备中英双语 `i18n`、语义化 CSS 令牌、36 个动作的统一操作目录（`actionCatalogData.ts`）、`Ctrl+Shift+P` 命令面板与 9 项自动化门禁（`scripts/verify.mjs`）。

### 2.2 三大结构性矛盾

| 矛盾维度 | 客观事实与源码证据 | 核心风险 |
|---|---|---|
| **1. 定位与维护面膨胀** | 底部已内置保活 LazyGit，但应用内仍自建 41 项 `WriteKind`（`crates/git-core/src/dto/write.rs`）；`src/App.tsx`（460 行）、`AppShell.tsx`（511 行，67 props）、`MainWorkspace.tsx`（323 行，39 props）层层透传；`gate.rs`（557 行）与 `FileDiffView.tsx`（552 行）逼近 600 行单文件上限。 | 继续扩张 GUI 写能力边际收益递减，却成倍放大 Gate、i18n、确认态与维护成本。 |
| **2. 验收债与文档代差** | 代码已发 `v0.3.1`，但 `README.md`、`需求文档.md`、`docs/05-交接文档.md` 仍停在 `v0.2.x` 口径；`docs/15` 仍标“待评审确认”；`docs/verification/GUI-实机验收清单.md` **92 项全未勾选**；`useUpdateCheck.ts` 已取消 24h 节流而文档仍写存在节流；Linux/macOS 缺原生实机验收与签名。 | 质量处于“自动化可编译、真实写链路与跨平台黑盒”状态，对外口径失真透支信任。 |
| **3. 交互断层与实现缺陷** | `useStartupRestore.ts:53-59` 在未勾选恢复时仍打开最近仓库（逻辑反转）；`layout.css` 与 `refinement.css` 在 641–900px 断点冲突；`CompareView.tsx` 将 `_onDirectoryDiff`/`_onOpenCommit` 丢弃导致目录对比入口断链；`SettingsDialog.tsx` 底部“取消”不回滚即时生效项且 `GitConfigSection` 切 tab 丢草稿。 | 高频刚需闭环半截断链，且存在明确逻辑缺陷与潜在切仓竞态风险。 |

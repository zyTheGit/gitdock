# Git Graph MVP 需求冻结

> 状态：架构开发基线。变更须先更新决策记录与验收标准。

## 目标与非目标

MVP 是 Windows 优先、单窗口单仓库的 Git 图谱桌面应用。核心价值是：在不改变仓库状态的前提下，快速理解提交 DAG，并以显式 Base / Compare 双槽比较两个 Git ref。

MVP 不包含远程写操作、分支创建/删除/重命名、stash、merge、rebase、目录级比较、三 ref 比较或冲突解决 UI。冲突后只展示状态和终端接管提示，绝不自动 abort / quit。

## 冻结的交互与 Git 语义

| 领域 | 冻结决策 |
|---|---|
| 图谱范围 | “当前分支相关”是 HEAD 可达的全部提交；“全量”是 `--all`。二者分开显示与保存布局状态。 |
| 对比 | 初始 Base=HEAD、Compare 为空；单次 Ctrl+选择填 Compare。双槽固定为选择瞬间解析到的 OID。MVP 默认使用 `git diff base...compare`，标题为“Compare 相对 Base 共同祖先的改动”；允许切换 `git diff base compare` 查看两端快照完整差异。 |
| 搜索 | 点击搜索结果后按需加载目标页、居中高亮并打开详情；随后关闭弹窗并清空查询，重新打开从空白搜索开始。 |
| 提交详情 | merge commit diff 相对第一父提交，必须标注。 |
| 搜索 | 搜索当前视图 ref 范围；message、至少 7 位 hash 前缀、author 姓名/邮箱、改动路径；可取消。 |
| OID | 支持 SHA-1（40 位）和 SHA-256（64 位）；复制完整 OID，不假设固定长度。 |
| 写操作 | 仅单 commit cherry-pick / revert、已有本地分支 checkout、分支描述写入 local config；全部由 Git CLI 执行。 |
| 切换分支 | 先验证 `refs/heads/*`，再执行 `git switch --no-guess <branch>`；不自动猜测远程跟踪分支。有 dirty/staged/untracked 改动时的策略见 ADR 0002（待裁决）：不自动 stash/reset/clean/丢弃，推荐显式确认后由 Git 判定。 |
| 外部 diff | 仅文件级；以“可执行文件 + 参数数组”启动，严禁 shell 拼接。 |

## 不可违背的可靠性约束

1. Git 读取层只读；任何改变工作区、index 或 refs 的操作只走 Git CLI。
2. 写前 Gate 必须检查干净工作区、中断态、`index.lock`、非 detached HEAD 和非 merge commit。
3. 写操作结果以退出码与之后检测到的 `CHERRY_PICK_HEAD` / `REVERT_HEAD` 判定，不能解析 stderr 文本猜测冲突。
4. 所有 Git 状态路径由 `git rev-parse --git-path` 取得，以兼容 linked worktree。
5. 每次异步读取带 repository generation；过期读取结果不得覆盖新 UI 状态。
6. bare repository 仅只读；submodule 只展示 gitlink OID 变化，不递归管理。

## MVP 对外验收结果

- 用户可打开普通仓库或 linked worktree，看到当前分支或全量 DAG 的首 200 条提交。
- 分页追加不改变已经可见提交的 lane；尚未加载父提交的边处于待连接状态。
- 用户可比较两个 ref、读取文件级 diff，并明确知道三点 diff 的方向性。
- 用户可安全执行允许的单提交操作；失败、冲突和恢复态均不会被误报为成功。
- 所有大文件、二进制、gitlink、编码无法可靠解析的内容均降级展示而不崩溃。

## 变更控制

以下变化视为架构级变更，必须先形成 ADR：diff 语义、Git 写入边界、OID 支持范围、图谱分页/稳定 lane 契约、支持的平台集合及最低 Git 版本。

# T23：分支对比后端契约与双向差异计算

- **波次**：Wave A（底座）
- **优先级**：P0
- **前置依赖**：无
- **是否需要 ADR**：是（扩展 `CompareResultDto` 与 `ChangedFileDto` 契约）
- **可并行性**：可与 T26 并行；T24、T25 必须等待本任务
- **粗略成本**：1 人日

---

## 1. 背景与目标

当前 `GitReadModule::compare` 只返回 Compare 侧引入的提交列表，且 `ChangedFileDto` 不携带改动归属信息，导致前端无法展示 Base 独有提交，也无法识别分叉分支中“两侧均改”的高风险文件。

目标：扩展对比契约，在不引入全量内容 diff 开销的前提下，补齐 Base 独有提交列表、分叉点摘要与文件级改动归属（`change_origin`）。

---

## 2. 范围与边界

### In Scope

1. 在 `crates/git-core/src/dto/compare.rs` 新增枚举 `CompareChangeOrigin`（`both` / `compare_only` / `base_only`）。
2. 在 `ChangedFileDto` 增加可选字段 `#[serde(default, skip_serializing_if = "Option::is_none")] pub change_origin: Option<CompareChangeOrigin>`。
3. 在 `CompareResultDto` 增加字段：
   - `pub base_commits: Vec<CommitSummaryDto>`
   - `pub base_commits_truncated: bool`
   - `#[serde(default, skip_serializing_if = "Option::is_none")] pub merge_base_summary: Option<String>`
4. 在 `crates/git-read/src/read/compare.rs` 实现：
   - 以 `merge_base` 可达集合为停止集，按提交时间倒序遍历 `base` 独有提交（上限 `DEFAULT_PAGE_LIMIT = 200`）。
   - 存在 `merge_base` 时，读取分叉点提交首行摘要写入 `merge_base_summary`。
   - 存在 `merge_base` 时，分别收集 `merge_base → base` 与 `merge_base → compare` 的改动文件路径集合，为 `files` 每项填充 `change_origin`（路径级归属判定）。
   - 无 `merge_base`（`two_dot_fallback`）及工作区对比（`worktree_compare.rs`）中，`base_commits` 为空、`change_origin` 为 `None`。
5. 同步更新 `src/shared/types.ts`、`docs/03-技术架构.md`，并在 `docs/adr/` 新增契约变更 ADR。
6. 在 `crates/git-read/tests/read_detail_compare.rs` 补充单测：分叉双向提交、快进/落后、两侧均改/单侧改动（三点与两点模式）、无共同祖先降级、工作区对比。

### Out of Scope

- 不修改前端对比 UI（归属 T24、T25）。
- 不做内容级冲突预演（不做 `git merge-tree`），仅做路径级“两侧均改”识别。
- 不改变既有 `compare_sides_file_diff` 单文件 diff 语义。

## 4. 关键设计约束

- 依赖方向不变：`git-read` 仅向下依赖 `git-core`，不引入新外部 crate。
- `change_origin` 必须使用 `#[serde(default, skip_serializing_if = "Option::is_none")]`，确保非对比接口（如单次提交详情）零冗余输出。
- 重命名文件（`old_path -> path`）在做路径集合交集时，需同时纳入新旧路径或按当前 `path` + `old_path` 匹配，避免漏报两侧均改。
- `crates/git-read/src/read/compare.rs` 保持在 `600` 行以内；必要时将辅助遍历函数拆出独立子模块。

## 6. 验收标准

- **Given** 分叉的两个分支（Base 独有 2 提交、Compare 独有 3 提交，且均修改了 `a.txt`），**When** 调用三点对比，**Then** `base_commits.len() == 2`、`commits.len() == 3`、`merge_base_summary` 非空、`a.txt` 的 `change_origin == Some(Both)`。
- **Given** 上述分叉分支，**When** 调用两点快照对比，**Then** 仅 Base 修改的文件标记 `BaseOnly`，仅 Compare 修改的文件标记 `CompareOnly`，双方均修改的文件标记 `Both`。
- **Given** Compare 为 Base 祖先（落后状态），**When** 调用三点对比，**Then** `commits` 为空、`base_commits` 非空、`base_only > 0`。
- **Given** 工作区对比或无共同祖先对比，**When** 调用对比接口，**Then** `base_commits` 为空、`change_origin` 为 `None`，无 panic 或报错。
- **Given** 执行 `cargo test -p git-core -p git-read` 与 `npm run build`，**When** 校验结束，**Then** 全部通过且触及文件不超过 600 行。

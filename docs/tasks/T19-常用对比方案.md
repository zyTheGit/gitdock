# T19：常用对比方案

- **波次**：Wave 2（核心工作流补强）
- **优先级**：P1
- **前置依赖**：T16
- **是否需要 ADR**：否（首版仅前端 OID 快照与 localStorage）
- **可并行性**：依赖 T16 完成后，可与 T18、T20 并行
- **粗略成本**：2–4 人日

---

## 1. 背景与目标

当前 Base / Compare 只按仓库标签保存在内存中，重启或重新选择后无法恢复常用对比组合。

目标：允许用户按仓库收藏、命名、应用和删除对比方案，首版保存 OID 快照，不跟随移动 ref。

---

## 2. 范围与边界

### In Scope

1. 在 CompareBar 增加“收藏当前对比”入口和方案列表入口。
2. 收藏条件：
   - Base 与 Compare 均已选择。
   - 两侧均为提交 OID。
   - 首版不支持工作区槽位。
3. 方案数据：
   - 名称。
   - Base OID / 展示标签。
   - Compare OID / 展示标签。
   - 创建时间。
4. 按仓库路径隔离，使用带 schema 版本的 `localStorage` 键。
5. 支持应用、删除和空态。
6. 应用后复用既有 `slots.setSide` / 对比加载流程，不新增 Git 读取通道。
7. 损坏或不兼容的本地数据安全忽略，不阻塞应用启动。

### Out of Scope

- 不支持跟随分支移动的 ref 语义。
- 不支持工作区快照方案。
- 不支持跨设备同步、导入导出或团队共享。
- 不修改 DTO、Tauri command 或后端存储。
- 不改变三点 / 两点切换和 CompareBar 的 pending 替换逻辑。

## 4. 关键设计约束

- 存储键必须编码仓库路径，避免不同仓库互相污染。
- 本地存储属于外部输入边界，必须校验 schema、OID 和标签类型。
- OID 快照失效时进入既有 `invalidRef` / 对比错误展示，不静默替换为其他提交。
- 收藏名称去除首尾空白，空名称不可提交。
- 方案操作不得触发写操作或仓库刷新。
- 不增加动画。

---

## 5. 实施步骤

1. 定义方案类型、schema 版本和按仓库隔离的存储键。
2. 实现 localStorage 读取、校验、写入和删除纯函数及单测。
3. 在 CompareBar 增加收藏与方案列表入口。
4. 实现名称输入、空态、应用和删除交互。
5. 应用方案时复用既有槽位设置与对比加载。
6. 验证重启、仓库切换、损坏数据和失效 OID。

---

## 6. 验收标准

- **Given** Base / Compare 已选择两个提交，**When** 点击收藏并输入名称，**Then** 方案按当前仓库保存。
- **Given** 关闭并重启应用，**When** 打开同一仓库的方案列表，**Then** 已收藏方案仍存在。
- **Given** 打开多个仓库，**When** 查看方案列表，**Then** 只显示当前仓库的方案。
- **Given** 应用某方案，**When** 加载完成，**Then** Base / Compare 与保存的 OID 一致，三点 / 两点偏好保持当前状态。
- **Given** 保存的 OID 已不存在，**When** 应用方案，**Then** 显示既有引用失效 / 对比错误，不静默改写槽位。
- **Given** localStorage 中存在损坏数据，**When** 打开方案列表，**Then** 安全显示空态，应用不崩溃。
- **Given** 一侧为工作区或未选择，**When** 查看收藏入口，**Then** 收藏不可用并显示原因。
- **Given** 执行 `npm run check`，**When** 校验结束，**Then** 全部门禁通过，触及文件满足行数限制。

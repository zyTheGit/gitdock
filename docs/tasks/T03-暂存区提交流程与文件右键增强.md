# T03：暂存区提交流程内嵌与文件右键增强

- **波次**：Wave 1（体验优化）
- **优先级**：P0
- **前置依赖**：建议在 T01 后执行
- **是否需要 ADR**：仅当新增「在系统文件管理器中显示文件」Tauri command 时，需在 `docs/adr/` 补充简短 ADR（并纳入 `src-tauri/src/app/platform/` 平台适配层）；若只做前端内嵌表单与外部 diff 复用则无需 ADR
- **可并行性**：可与 T02、T04、T05 并行

---

## 1. 背景与目标

当前暂存区（[StagingView.tsx](file:///C:/zy/project_other/ai-projects/git-graph/src/features/staging/StagingView.tsx)）的日常提交体验有三处摩擦：
1. 每次提交都必须点顶部按钮打开全屏遮罩的 [CommitMessageDialog.tsx](file:///C:/zy/project_other/ai-projects/git-graph/src/features/staging/CommitMessageDialog.tsx)，遮挡了右侧正在核对的 diff 与左侧已暂存清单；取消关闭后草稿也会丢失。
2. 顶栏的 [WorkspaceBadge.tsx](file:///C:/zy/project_other/ai-projects/git-graph/src/app/WorkspaceBadge.tsx) 显示工作区改动数，但不能点击直达暂存区。
3. 暂存区文件列表缺少右键菜单（无法复制文件路径、无法用外部工具对比、无法在系统文件管理器中定位该文件）。

---

## 2. 范围（In Scope）与边界（Out of Scope）

### In Scope
1. **提交表单内嵌至暂存区左侧栏底部（`CommitComposer.tsx`）**：
   - 从 `CommitMessageDialog.tsx` 抽出可复用的提交表单组件，常驻在 `StagingView` 左侧列表下方（支持折叠/展开，保留 `Ctrl/Cmd+Enter` 快捷提交）；
   - 输入草稿在同仓库会话内切回图谱再回暂存区时不丢失（按 `repo.path` 暂存内存或 `sessionStorage`，切仓库或提交成功后清空）；
   - 保留 **amend** 勾选与 `read_head_message` 预填；**重要**：amend 属于历史改写，点击提交后仍必须弹出专门的二次确认 Modal（展示被替换 HEAD 与 reflog 恢复指引），不得简化掉确认步骤；
   - 普通 `create_commit` 走 Gate 校验后直执，Gate 拒绝项与 hook stderr 就地展示在表单内。
2. **顶栏 `WorkspaceBadge` 可点击进入暂存区**：
   - 将 `WorkspaceBadge` 改为语义化 `<button>`（bare 仓库保持只读/禁用），点击切换进入或退出暂存区视图，并补充 hover 样式与 `title` 提示。
3. **暂存区文件右键菜单**：
   - 为 `StagingFileList` 行增加 `onContextMenu` 回调，弹出 `ContextMenu`，包含：
     - 暂存 / 取消暂存该文件
     - 复制相对路径
     - 在系统文件管理器中显示（新增受限 command `reveal_in_file_manager(path)`：仅接受当前仓库内相对路径，禁止路径穿越 `..`，由 `src-tauri/src/app/platform/` 平台适配层按 Windows `explorer /select,` / macOS `open -R` / Linux 打开父目录实现）
   - 若外部工具对比支持工作区路径有复杂性，可仅对已有能力接入，不强行破坏 `external.rs` 现有语义。

### Out of Scope
- 不在本任务实现「丢弃改动」（归属 T06）或「Hunk 级暂存」（归属 T07）。
- 不允许 `reveal_in_file_manager` 接受任意绝对路径（必须限制在当前已打开仓库根目录内，经 `canonicalize` + `starts_with` 校验）。

## 4. 关键设计约束

- **安全边界**：`reveal_in_file_manager` 必须校验 `path` 为相对路径、拒绝 `..`、拼接仓库根路径后 `canonicalize` 确认仍在仓库根内；启动系统文件管理器只走参数数组，绝不走 `cmd /C` 或 `sh -c`。
- **Esc 分层协议**：内嵌表单普通态不拦截全局 Esc 退出暂存区（或输入框聚焦时按 Esc 先失焦再退出）；amend 确认弹窗仍按捕获阶段 `consumeEsc` 只关闭确认框。
- **行数控制**：`StagingView.tsx` 现有 469 行，务必通过拆分 `CommitComposer.tsx` 控制在 450 行以内。

## 5. 验收标准

- **Given** 进入暂存区，**When** 在左侧下方编写提交说明同时切换查看右侧不同文件的 diff，**Then** diff 始终可见无遮挡，草稿不丢失；按 `Ctrl/Cmd+Enter` 可正常创建提交并刷新图谱。
- **Given** 勾选「修改上次提交（amend）」，**When** 点击提交，**Then** 必须先弹出专门的历史改写确认框并展示被替换 HEAD 信息与 reflog 提示，确认后才执行。
- **Given** 顶栏显示工作区脏状态徽标，**When** 点击该徽标，**Then** 立即切入暂存区视图。
- **Given** 右键暂存区某文件，**When** 点击「复制相对路径」或「在文件管理器中显示」，**Then** 行为正确；传入 `../outside` 等越界路径时后端拒绝并返回 `InvalidArgument` 错误。
- **Given** 执行 `npm run check`，**When** 校验结束，**Then** IPC 契约、i18n、Rust 测试、前端构建全绿，所有触及文件 ≤ 600 行。

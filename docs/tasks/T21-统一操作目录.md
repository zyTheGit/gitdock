# T21：统一操作目录

- **波次**：Wave 3（操作发现性）
- **优先级**：P1
- **前置依赖**：T14–T20
- **是否需要 ADR**：否（前端动作编排，不新增执行通道）
- **可并行性**：需等前序任务收口；T22 必须等待本任务
- **粗略成本**：3–4 人日

---

## 1. 背景与目标

当前操作散落在顶栏、标签栏、侧栏、图谱右键、暂存区和设置中。直接做命令面板会把重复入口搬进搜索框，无法解决重复和漂移。

目标：先建立统一操作目录，让菜单、快捷键帮助和后续命令面板共享同一份动作定义、可用条件和执行回调。

---

## 2. 范围与边界

### In Scope

1. 定义统一动作描述：
   - 稳定动作 ID。
   - 标题 i18n key。
   - 上下文（全局 / 图谱 / 对比 / 暂存区 / 引用）。
   - 可用条件与禁用原因。
   - 快捷键（若有）。
   - 执行回调。
2. 首批接入：
   - 顶栏导航与刷新、设置。
   - 打开 / 关闭 / 切换仓库标签。
   - 引用定位、创建分支、对比分支。
   - 图谱行高频操作。
   - 暂存区高频操作。
   - 终端切换。
3. 同一动作在不同入口使用同一 ID 和执行回调。
4. 提供目录纯函数测试，覆盖上下文过滤、busy、bare、无仓库和无选中对象。
5. 为 T22 提供稳定查询接口。

### Out of Scope

- 不新增 Git 写能力。
- 不让目录直接调用 IPC；所有动作仍走既有 hook / 回调。
- 不在本任务实现命令面板 UI。
- 不删除仍需要的右键菜单和上下文入口。
- 不强制把所有低频一次性操作都塞进目录。

## 4. 关键设计约束

- 动作 ID 稳定，不用显示文案作为身份。
- 目录只描述动作，不拥有第二套仓库状态或写流程。
- 禁用判断必须考虑 busy、bare、无仓库、无选中提交、对比槽位和中断态。
- 菜单 / 按钮 / 命令面板必须复用同一执行入口，避免 Gate 绕过。
- 单文件不超过 400 行；按上下文或动作域拆分目录数据。
- 不增加用户可见动画。

---

## 5. 实施步骤

1. 盘点前序任务完成后的所有高频入口。
2. 定义动作类型、上下文和禁用原因模型。
3. 在 `AppShell` 装配统一动作回调。
4. 将首批菜单和按钮接到动作目录。
5. 为目录过滤和可用性编写纯函数测试。
6. 确认原右键菜单、顶栏和暂存区行为没有回退。

---

## 6. 验收标准

- **Given** 同一动作在顶栏、右键菜单和目录中各有一处定义，**When** 执行任一入口，**Then** 调用同一回调并得到一致结果。
- **Given** 无仓库或 busy，**When** 查询目录，**Then** 不相关动作被过滤，不可执行动作带禁用原因。
- **Given** bare 仓库，**When** 查询工作区相关动作，**Then** 动作不可用。
- **Given** 对比槽位未完成，**When** 查询打开对比结果动作，**Then** 动作禁用或走既有选择流程。
- **Given** 中断态仓库，**When** 查询写动作，**Then** 继续沿用既有 Gate / interruption 约束。
- **Given** 执行目录单测，**When** 校验结束，**Then** 上下文过滤和禁用条件全部通过。
- **Given** 执行 `npm run check`，**When** 校验结束，**Then** 全部门禁通过，触及文件满足行数限制。

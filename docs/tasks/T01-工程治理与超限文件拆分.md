# T01：工程治理、超限文件拆分与 npm 许可证门禁

- **波次**：Wave 0（前置任务，解除后续多模型并行的文件冲突与行数瓶颈）
- **优先级**：P0
- **前置依赖**：无
- **是否需要 ADR**：否（纯代码拆分与门禁建设，不改变对外契约与运行时行为）
- **可并行性**：建议独占执行，完成后再启动 Wave 1 / Wave 2

---

## 1. 背景与目标

当前仓库有 5 个存量源码/测试文件已超过 `AGENTS.md` 的 **600 行硬上限**，且 `src/App.tsx` 已达 591 行（距离红线仅剩 9 行）；同时前端 npm 依赖缺少与 Rust `deny.toml` 对齐的许可证门禁（`docs/12` R2）。

本任务目标：
1. 将所有超 600 行文件及濒临超限的 `src/App.tsx` 按职责做**纯移动拆分**，为后续并行开发扫清障碍。
2. 补齐前端 npm 许可证门禁并接入 `scripts/verify.mjs` 与 CI。
3. 顺带对齐 `docs/03-技术架构.md` 与现状模块清单（对应 `docs/12` R3 残留检查）。

---

## 2. 范围（In Scope）与边界（Out of Scope）

### In Scope
1. **拆分 `crates/git-core/src/dto.rs`（现 772 行，对应 `docs/12` R6）**：
   - 改为 `crates/git-core/src/dto/` 目录模块（`mod.rs` 统一 `pub use`，对外路径与序列化格式 100% 保持不变）：
     - `repo.rs`（仓库 / ref / head / interruption / warning / branch description）
     - `graph.rs`（`GraphScope` / `CommitSummaryDto` / `GraphPageDto` / 布局 DTO）
     - `diff.rs`（`FileStatus` / `ChangedFileDto` / `CommitDetailDto` / `FileDiffDto`）
     - `compare.rs`（对比与搜索 DTO、`CommitBranchContextDto`）
     - `write.rs`（`WriteKind` / `PullMode` / `WriteRequest` / `GateReportDto` / `WriteOutcomeDto` / `WorkspaceStatusDto` / `Staging*` / `StashEntryDto` + 既有单测）
2. **拆分 `crates/git-read/src/diff.rs`（现 614 行）**：
   - 按职责拆分为 `crates/git-read/src/diff/`（例如 `mod.rs` / `tree_changes.rs` / `patch.rs` / `tests.rs`），严格遵守 `git-read` 只读静态守卫。
3. **拆分 3 个超限 Rust 集成测试文件**：
   - `crates/git-write/tests/write_integration.rs`（现 1063 行）→ 按场景拆成多个独立集成测试文件（如 `write_commit_flow.rs` / `write_branch_switch.rs` / `write_staging.rs` / `write_interruption.rs`，公共辅助放 `crates/git-write/tests/common/mod.rs`）。
   - `crates/git-read/tests/v2_readonly.rs`（现 810 行）→ 按只读查询与静态审计拆成 2–3 个文件。
   - `crates/git-read/tests/read_integration.rs`（现 643 行）→ 按 refs/detail/compare/search 拆分。
4. **`src/App.tsx` 瘦身（现 591 行 → 目标 ≤ 420 行）**：
   - 拆出 `src/app/AppDialogs.tsx`（收拢 `SearchView`、`AppMenus`、`BranchDescriptionDialog`、`TagDescriptionDialog`、`ConfirmWriteDialog`、`BranchCompareDialog`、`SettingsDialog`、`refs.dialogs`、`stash.dialog` 渲染）；
   - 如仍偏大，可拆出 `src/app/MainWorkspace.tsx`（收拢 `CompareView` / `StagingView` / `GraphPane + CommitDetailPane` 切换）。
5. **npm 许可证门禁（对应 `docs/12` R2）**：
   - 新增 `scripts/check-npm-licenses.mjs`（零外部依赖，直接解析 `package-lock.json` 中所有包及其 `node_modules/*/package.json` 的 `license` 字段）；
   - 白名单与 Rust `deny.toml` 保持一致（MIT / Apache-2.0 / BSD-2-Clause / BSD-3-Clause / ISC / MPL-2.0 / CC0-1.0 / Unicode-3.0 / 0BSD / Unlicense 等宽松许可），显式拒绝 GPL / AGPL / LGPL 及未识别许可证；
   - 接入 `scripts/verify.mjs`（作为独立门禁步骤，CI 三平台自动生效）。

### Out of Scope
- 禁止顺手重构任何业务逻辑、修改字段名或改变现有 UI/API 行为。
- 禁止修改版本号或升级依赖。

---

## 3. 关键设计约束

- **纯移动原则**：所有 Rust 公开类型继续通过 `git_core::*`、`git_read::*` 原路径导出，不得破坏任何下游 crate 或测试 import。
- **静态守卫兼容**：拆分 `crates/git-read/src/diff.rs` 后，确认 `v2_readonly` 里的静态扫描逻辑仍覆盖整个 `crates/git-read/src/` 目录（递归扫描所有 `.rs` 文件）。
- **单文件行数**：拆分后所有涉及的源码、测试、脚本文件均须 **≤ 400 行**（最坏 ≤ 500 行）。

---

## 4. 分步实施指引

1. 先拆分 `crates/git-core/src/dto.rs` → `dto/` 子模块并确认 `git_core::*` re-export 完整。
2. 拆分 `crates/git-read/src/diff.rs` → `diff/` 子模块，检查 `v2_readonly` 静态守卫覆盖路径。
3. 拆分 3 个超限集成测试文件，确保所有既有测试用例名称/断言完整保留、零删减。
4. 拆分 `src/App.tsx` 渲染层到 `src/app/AppDialogs.tsx`（及按需 `MainWorkspace.tsx`），保持零行为变化。
5. 实现 `scripts/check-npm-licenses.mjs` 并接入 `scripts/verify.mjs`，自测白名单通过与模拟非法许可证拒绝两种路径。
6. 核对 `docs/03-技术架构.md` 模块树，同步拆出的新目录说明。
7. 跑全量 `npm run check` 并检查所有触及文件行数。

---

## 5. 验收标准

- **Given** 运行全量门禁 `npm run check`，**When** 全部步骤完成，**Then** 版本号、i18n、IPC 契约、npm 许可证检查、`npm run build`、`cargo fmt --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` 全部通过，且 Rust 测试总数不少于拆分前。
- **Given** 统计整个仓库 `src/` 与 `crates/` 与 `src-tauri/` 源码和测试文件行数，**When** 检查本次所有触及文件，**Then** 没有任何文件超过 600 行，且 `src/App.tsx` ≤ 450 行。
- **Given** `scripts/check-npm-licenses.mjs` 遇到 GPL 或未知许可证条目，**When** 执行脚本，**Then** 以非零退出码失败并打印包名与许可证值。

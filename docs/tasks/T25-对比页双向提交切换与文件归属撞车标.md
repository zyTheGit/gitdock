# T25：对比页双向提交切换与文件归属撞车标

- **波次**：Wave B（对比 UI）
- **优先级**：P0
- **前置依赖**：T23
- **是否需要 ADR**：否（前端对比列表能力增强）
- **可并行性**：可与 T24、T26、T27 并行
- **粗略成本**：1 人日

---

## 1. 背景与目标

目前左侧提交区只展示 Compare 侧提交，且文件列表无法识别“两侧均改”的冲突高风险文件；在两点快照模式下，也无法分辨文件差异来自 Base 还是 Compare。

目标：为左侧提交区增加双向切换能力，并为文件列表与筛选栏补齐「两侧均改」撞车标、两点归属标及一键筛选。

---

## 2. 范围与边界

### In Scope

1. **双向提交列表（`CompareCommitList.tsx`）**：
   - 接收 `compareCommits` / `compareTruncated` 与 `baseCommits` / `baseTruncated` 以及两侧名称（`compareLabel` / `baseLabel`）。
   - 顶部提供紧凑双向切换胶囊：`[ <Compare> 独有 (N) ]` / `[ <Base> 独有 (M) ]`。
   - **自动聚焦逻辑**：切换对比对时，默认选 Compare 侧；若 `compareCommits.length === 0 && baseCommits.length > 0`，自动切到 Base 侧。
   - 工作区对比时隐藏双向切换，保留“工作区无提交历史”简短说明。
   - 保持虚拟滚动、高度拖拽、点击打开详情与右键菜单不变。
2. **文件归属与撞车标（`CompareFileList.tsx`）**：
   - `change_origin === "both"`：在文件行展示醒目橙色小徽章「两侧均改」（`--warning` 语义令牌，带完整 `title` 说明）。
   - 两点快照模式下：`compare_only` / `base_only` 展示轻量归属标（如 `C` / `B`，`title` 显示真实分支名）。
   - 三点模式下 `compare_only` 不额外打标，保持列表清爽。
   - 扁平列表与目录树模式均正常展示徽章，不挤坏路径省略与 `+add/-del` 统计。
3. **一键筛选撞车文件（`CompareStatusFilter.tsx` & `CompareView.tsx`）**：
   - 在状态筛选栏旁增加「仅看两侧均改 (K)」开关按钮（仅当存在 `both` 文件时展示）。
   - 与路径过滤、状态筛选（A/M/D/R）以 AND 逻辑组合生效；当前选中文件被筛掉时自动回落到首个可见文件。
4. 同步更新中英文 i18n 文案与样式。

### Out of Scope

- 不实现点击提交后在对比页内过滤文件（归属二期）。
- 不修改右侧 `FileDiffView` 代码对比渲染逻辑。

## 4. 关键设计约束

- 切换 Compare / Base 提交列表时，重置虚拟列表滚动位置到顶部。
- 文件行内徽章使用 `flex: none`，路径列 `min-width: 0; overflow: hidden; text-overflow: ellipsis`，确保长文件名在 300px 侧栏内不撑破布局。
- 对比对象变化（`base.oid` 或 `compare.oid` 变更）时，重置「仅看两侧均改」开关，避免残留筛选导致误判为空。

## 6. 验收标准

- **Given** 分叉对比（两侧均有独有提交），**When** 点击提交区切换胶囊，**Then** 可顺畅在 Compare 独有与 Base 独有提交间切换，虚拟滚动正常。
- **Given** Compare 落后于 Base（Compare 独有 0、Base 独有 > 0），**When** 打开对比页，**Then** 提交区自动选中 Base 独有侧并展示列表。
- **Given** 存在两侧同时修改的文件，**When** 查看文件列表并开启「仅看两侧均改」，**Then** 撞车文件显示橙色徽章且筛选后仅保留这些文件。
- **Given** 切换到两点快照模式，**When** 查看文件列表，**Then** 可清晰区分 `仅 Base`、`仅 Compare` 与 `两侧均改`。
- **Given** 执行 `npm run check`，**When** 校验结束，**Then** 全部门禁通过，所有触及文件 <= 600 行。

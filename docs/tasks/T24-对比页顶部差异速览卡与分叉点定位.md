- **波次**：Wave B（对比 UI）
- **优先级**：P0
- **前置依赖**：T23
- **是否需要 ADR**：否（纯前端展示与交互升级）
- **可并行性**：可与 T25、T26、T27 并行
- **粗略成本**：1 人日

---

## 1. 背景与目标

当前 `CompareHeader` 标题抽象（`Compare 相对 Base 共同祖先的改动`），双向提交数藏在角落灰字中，且没有展示分叉点与按状态拆解的文件统计，用户进入对比页后无法一眼判断两个分支的关系。

目标：将对比页顶部重构为紧凑的「差异速览卡」，用真实引用名、拓扑状态徽章、微型双向比例条与分叉点定位入口，让用户第一眼读懂两个分支的区别。

---

## 2. 范围与边界

### In Scope

1. 重构 `CompareHeader.tsx`（或拆出 `CompareSummaryCard.tsx`），按 6 种场景自动判定并展示主结论：
   - **可快进（领先）**：`<Compare>` 领先 `<Base>` N 提交
   - **已落后**：`<Compare>` 落后 `<Base>` N 提交
   - **已分叉**：`<Base>` 独有 M · `<Compare>` 独有 N
   - **完全一致**：两者指向同一提交
   - **无共同祖先**：已降级为两端完整快照
   - **工作区 / 两点快照**：`<Base> → <Compare>` 完整快照差异（不展示冗余分叉条）
2. 渲染微型**双向比例条（Ahead / Behind Bar）**，在领先 / 落后 / 分叉态下直观呈现两侧提交量级比例。
3. 展示**分叉点入口**：存在 `result.merge_base` 时展示 `分叉于 <short_oid>`（`title` 含 `merge_base_summary`），点击后切回图谱视图并定位聚焦到该 `merge_base` 提交。
4. 展示**紧凑变更统计**：总文件数 + 按状态拆解计数（如 `A 3 · M 8 · D 1 · R 1`，零值省略）+ `+totalAdd / -totalDel`。
5. 优化模式切换文案为意图导向：`仅看分支改动 (...)` vs `两端完整快照 (..)`（`title` 保留 Git 命令说明）。
6. 当三点模式下 `compare_only == 0 && base_only > 0`（Compare 落后于 Base）时，空态提示条给出更明确的中文/英文引导。
7. 同步更新中英文 i18n 资源与主题令牌样式。

### Out of Scope

- 不修改提交列表与文件列表的内部交互（归属 T25）。
- 不修改 `CompareBar` 双槽栏布局。
- 不修改图谱悬浮卡（归属 T27）。

## 4. 关键设计约束

- 速览卡保持紧凑，不挤压下方文件列表与 Diff 主区高度。
- 长分支名必须支持省略号截断并通过 `title` 保留完整名称。
- 比例条与状态徽章仅使用 `tokens.css` 语义令牌，深浅主题下对比度清晰。
- 纯计算逻辑（拓扑判定、统计拆解）抽离至 `compareSummary.ts`，便于单测与复用。

## 6. 验收标准

- **Given** 对比两个已分叉分支，**When** 进入对比页，**Then** 顶部直接显示 `已分叉`、真实分支名、双向比例条、分叉点短 hash 与 `A/M/D/R` 文件统计。
- **Given** 点击分叉点短 hash，**When** 页面切换，**Then** 返回图谱并高亮定位到对应 `merge_base` 提交行。
- **Given** 对比快进、落后、同一提交、工作区、无共同祖先场景，**When** 查看顶部，**Then** 结论文案准确，工作区/两点模式不出现无关分叉噪音。
- **Given** 窄窗口（如 800px）与长分支名，**When** 查看速览卡，**Then** 不发生文字重叠或横向溢出。
- **Given** 执行 `npm run check`，**When** 校验结束，**Then** 全部门禁通过，所有触及文件 <= 600 行。

# T15：远程同步工具栏收口

- **波次**：Wave 1（首屏精简）
- **优先级**：P0
- **前置依赖**：无
- **是否需要 ADR**：否（只调整既有远程动作的前端组织）
- **可并行性**：可与 T14、T16、T17 并行
- **粗略成本**：1–2 人日

---

## 1. 背景与目标

图谱工具栏当前常驻 Fetch、Fetch + prune、Pull 模式下拉、Pull、Push 五个控件，挤占范围筛选、提交计数和恢复入口。

目标：收为 `Fetch ▾ / Pull ▾ / Push` 三个控件，保留每种操作的明确语义和现有 Gate / busy / 错误反馈。

---

## 2. 范围与边界

### In Scope

1. `Fetch ▾` 菜单提供：
   - Fetch。
   - Fetch + prune。
2. `Pull ▾` 菜单提供：
   - Pull（ff-only）。
   - Pull（merge）。
3. `Push` 保留为直接按钮。
4. 所有远程动作共享 busy 状态：任一动作执行中，三个控件和菜单项均禁用。
5. 执行中文案即时切换为 fetching / pulling / pushing，菜单在动作开始后关闭。
6. 保留现有远程错误横幅、关闭按钮和刷新后重读。
7. 更新 `aria-label`、`title` 和双语文案。

### Out of Scope

- 不修改远程写请求、Gate、凭据策略或 ADR-0010 的执行语义。
- 不新增自动 fetch / pull / push。
- 不新增 force push。
- 不把 Pull 和 Push 合并为语义模糊的“同步”。
- 不改变多 Remote 支持范围。

## 4. 关键设计约束

- 菜单项必须明确写出 ff-only / merge，不能仅依靠图标或 tooltip 区分。
- 菜单打开和关闭不触发 Git 操作。
- 执行中不得通过快速连点重复提交。
- 菜单支持键盘 ↑↓ / Enter / Esc，焦点在关闭后回到触发按钮。
- 工具栏在 1280×800 与窄窗口下均不得横向溢出。
- 不增加装饰动画。

---

## 5. 实施步骤

1. 核查 `useRemoteActions` 的 `run` / `setPullMode` / busy / error 接口。
2. 实现三控件远程动作组件和键盘菜单。
3. 将 Pull 菜单选择映射到既有 ff-only / merge 请求。
4. 将 Fetch + prune 保留在 Fetch 菜单，不删除能力。
5. 调整图谱工具栏布局和双语文案。
6. 验证正常、禁用、执行中、失败和菜单键盘路径。

---

## 6. 验收标准

- **Given** 仓库具备远程能力，**When** 查看图谱工具栏，**Then** 只显示 Fetch、Pull、Push 三个主控件，不再常驻 Pull 模式下拉和独立 prune 按钮。
- **Given** 打开 Fetch 菜单，**When** 选择 Fetch + prune，**Then** 执行既有 prune 流程，结果和错误反馈与改造前一致。
- **Given** 打开 Pull 菜单，**When** 选择 ff-only 或 merge，**Then** 请求模式与菜单文案一致。
- **Given** 任一远程动作执行中，**When** 尝试点击其他远程控件或菜单项，**Then** 全部禁用，不产生第二次请求。
- **Given** 远程动作失败，**When** 查看结果，**Then** 错误横幅仍保留 stderr / 说明和关闭入口。
- **Given** 使用键盘操作菜单，**When** 按 Esc，**Then** 只关闭菜单，不退出图谱、搜索或对比视图。
- **Given** 执行 `npm run check`，**When** 校验结束，**Then** 全部门禁通过，触及文件满足行数限制。

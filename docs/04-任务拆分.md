# GitDock 开发任务拆分

> 本清单用于分派给其他智能体或开发者。每个任务应独立提交，禁止把未验证的后续能力混入当前任务。

## 阶段 0：验证与工程基线

| 编号 | 任务 | 前置 | 交付物 | 验收责任 |
|---|---|---|---|---|
| V1 | 创建可复现 Git fixture 生成器（线性、分叉、合并、tag、shallow、bare、linked worktree、SHA-256） | 无 | 夹具脚本与说明 | 测试智能体 |
| V2 | 验证 gix 只读链路与 OID 格式 | V1 | 读取结果与兼容性报告 | 测试智能体 |
| V3 | 验证 Tauri 分页 DTO、虚拟列表和大 diff 响应 | V1 | 性能记录 | 测试智能体 |
| V4 | 验证 CLI Gate、冲突、hook 拒绝、空 pick、worktree 占用与恢复 | V1 | 状态机结果表 | 测试智能体 |

V2–V4 是对既定选型的准入验证；失败时按 `02-选型终审.md` 的否决条件处理，不由验证任务自行改变架构。

## 阶段 1：最小可交付只读路径

| 编号 | 任务 | 依赖 | 产出 |
|---|---|---|---|
| M1 | 建立 Tauri 2 + React 工程、权限与配置目录 | V3 | 空壳应用与受限 command seam |
| M2 | 实现 `GitReadModule` 的打开仓库、HEAD、refs、GraphPage | V2, M1 | 分页 DTO |
| M3 | 实现 `GraphLayoutModule` 的稳定 lane 与 pending edge | M2 | 可渲染图谱增量 |
| M4 | 实现图谱虚拟列表、ref 标签与手动刷新 | M2, M3 | 当前分支视图 |
| M5 | 实现 commit 详情与单文件 diff 降级 | M2, M4 | 详情面板 |

阶段完成定义：能打开仓库，显示当前分支前 200 条提交、加载更多且 lane 不跳动，并显示 commit 详情。

## 阶段 2：核心对比与搜索

| 编号 | 任务 | 依赖 | 产出 |
|---|---|---|---|
| C1 | Base / Compare 双槽和 OID 固定规则 | M4 | 对比选择状态 |
| C2 | 默认三点 diff、可切换两点快照差异、ahead/behind 与路径过滤 | M2, C1 | 对比文件列表 / diff |
| C3 | 独立搜索结果视图与定位返回 | M2, M4 | 搜索体验 |
| C4 | 外部文件 diff 配置及参数数组启动 | C2 | 外部工具 adapter |

阶段完成定义：任意两个 ref 能完成定向三点对比，且无 merge-base 时有明确降级提示。

## 阶段 3：受控写操作与恢复

| 编号 | 任务 | 依赖 | 产出 |
|---|---|---|
| W1 | `GitWriteModule`、Gate 和操作互斥 | V4, M1 | 白名单操作执行器 |
| W2 | cherry-pick / revert 确认、结果状态机与恢复横幅 | W1 | 受控提交操作 |
| W3 | 切换已有本地分支 | W1, M4 | `switch --no-guess` 流程 |
| W4 | 分支描述的 local config 读写 | M2, W1 | 描述编辑交互 |

阶段完成定义：允许的写操作在成功、普通失败和冲突时均显示正确状态，仓库绝不被自动 abort / quit。

## 并行与串行约束

- V1 可最先开始；V2、V3、V4 可并行。
- M2 与 M3 必须先于 M4；M3 不等待任何 UI 实现。
- C1 与 C3 可并行；C2 依赖 C1。
- W1 是全部写操作的唯一前置，不允许各功能重复实现 Gate。
- 任意任务修改跨模块 DTO 时，必须更新 `03-技术架构.md` 的 interface 与不变量。

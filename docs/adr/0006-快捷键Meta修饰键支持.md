# ADR-0006：快捷键 Meta（⌘）修饰键支持

- 状态：已接受（2026-11-03，G3）
- 关联：ADR-0005（platform 模块与 `primaryModifierLabel`）、docs/09 差距清单 F-1

## 背景

快捷键体系（`src/shared/keybindings.ts`）只认 Ctrl/Alt：`matchesBinding` 对 `event.metaKey` 直接不命中、`useKeybindings` 对 metaKey 让路。macOS 用户按 ⌘+`（系统惯例位置）无法展开终端，物理 Ctrl 键虽可用但违背全系统惯例——G4 macOS 正式发布前必须解决（用户已裁决「完整支持」而非免责文案）。

## 决策

**存储规范不变，macOS 在显示层与监听层映射 ⌘**（display 映射方案）：

1. **存储格式保持 `Ctrl+…` 规范**。理由：localStorage 旧绑定零迁移成本；同一份设置跨平台语义一致；canonical 唯一性（⌘ 与 Ctrl 归一为同一绑定）天然成立。
2. **监听层**（`comboFromEvent`）：macOS 上 `ctrl: event.ctrlKey || event.metaKey`——用户按 ⌘+` 或物理 Ctrl+` 捕获/命中同一绑定。非 macOS 平台 Meta 不并入（Linux 的 Meta 组合保留给窗口管理）。`matchesBinding` 与 `useKeybindings` 移除对 `event.metaKey` 的硬性让路。
3. **显示层**：`splitCombo`（Kbd 组件的渲染源）与新增 `displaySpec`（整串文本，供 t() 插值）在 macOS 上把 `Ctrl` 键名显示为 `⌘`（复用 `primaryModifierLabel()`）。App 传给 StatusBar/TopBar/TerminalPanel 的 `terminalShortcut` 统一经 `displaySpec` 转换。
4. **校验语义不变**：macOS 捕获的 ⌘ 组合按 ctrl 分支校验——⌘+字母被拒绝（macOS 上 ⌘+字母是系统快捷键，拒绝理由文案已通用化为「Ctrl/⌘+字母」）；⌘+Alt 组合拒绝理由按平台选择（`keybindRejectCtrlAltMac`）。Shift 组合依旧拒绝。
5. **资源措辞**：`keybindRejectNoModifier` 的「⌘ 规划中」免责句改为正式说明（⌘ 与 Ctrl 等价均可录入）；`keybindRejectUnsupported` 改 `{{modifier}}` 插值。

## 替代方案（否决）

- **存储层引入 `Cmd` 修饰键**（spec 支持 `Cmd+…` 独立存储）：需要 parseSpec/formatCombo/校验/旧值迁移全链路改动，且产生「⌘ 与 Ctrl 两个绑定」的语义分叉与冲突判定复杂度；收益仅是显示层精确——显示映射已覆盖该需求。

## 验证

Windows 本地 tsc/build + check-i18n 门禁；macOS 行为（⌘ 命中/显示 ⌘/捕获规范化）属运行时行为，标注为 G4 实机验收项——CI 编译保证类型正确，`currentPlatform()` 分支逻辑由单元级静态审查保证。

## 影响

- keybindings.ts：comboFromEvent/matchesBinding/useKeybindings/splitCombo 改动 + displaySpec 新导出；DEFAULT_BINDINGS 与存储格式零变化。
- 消费方：App.tsx 三处 terminalShortcut 包 displaySpec；KeyBindingsSection 固定键位渲染映射 Ctrl→⌘；settings 域 2 个 key 措辞更新。
- 既有 Windows/Linux 行为零变化（metaKey 在非 mac 不并入、显示不映射）。

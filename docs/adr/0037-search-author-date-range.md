# ADR-0037：提交搜索支持作者日期区间

- 状态：已接受（2026-11-26 实现）
- 日期：2026-11-26
- 相关：`SearchRequest`、`git-read::search`、`src/features/search`、`docs/03-技术架构.md`

## 背景

搜索弹框目前只按关键词在提交信息、作者、Hash 前缀与改动路径中匹配。命中域标签仅收窄已返回结果，无法表达“只查某个日期范围内的提交”。日期条件若只放在前端，分页后的历史命中会被隐藏，语义不完整。

## 决策

1. `SearchRequest` 增加可选 `date_range`，包含 `from` 与 `to` 两个 Unix 秒边界：`from` 包含，`to` 不包含；任一端为空表示不限制。前端负责把本地日期换算为当天 0 点与次日 0 点，后端不感知时区。
2. 日期按提交的**作者时间** `authored_at` 过滤，与搜索结果显示日期一致；不使用索引中的 committer time。关键词仍必填，本能力只收窄已有文本检索，不提供纯日期浏览。
3. 日期判断在读取提交与作者签名后、字段与路径匹配前执行。总扫描计数与路径扫描计数分离：日期范围外的提交不消耗每页 2000 条的路径 diff 预算。
4. 区间是搜索会话的一部分：开始新搜索时生成新 `search_id` 并清空游标，后续 `load_more` 沿用同一区间。现有 cursor 载荷与编码不变。
5. 无效区间（两端均存在且 `from >= to`）返回 `InvalidArgument`；空区间等价于不筛选。
6. 已生效日期区间由前端 `useSearch` 持有，关闭搜索弹框后保留；未提交的日期修改只是组件草稿，重新打开时回到已生效区间。

## 影响与边界

- 改动 `SearchRequest` 属于跨层契约变更，需要同步 `git-core`、`src/shared/types.ts`、Tauri command 请求与架构文档。
- 搜索仍受每页 2 万条拓扑扫描上限约束。作者时间不在现有 `GraphIndex` 中，因此本次不提前按时间跳过提交对象读取；超大仓库查很早的日期范围可能需要多次“加载更多”。
- 本次不建立惰性作者时间索引，也不改变搜索结果的拓扑顺序。

## 备选方案（未采纳）

| 方案 | 不采纳原因 |
|---|---|
| 仅在前端过滤已返回结果 | 未加载的历史命中不会出现，分页结果不完整 |
| 按 committer time 过滤 | 可用索引时间提前跳过，但与结果行显示的作者日期不一致 |
| 允许无关键词的纯日期搜索 | 扩大搜索契约与扫描成本，当前需求不需要 |
| 同步给 `GraphIndex` 增加作者时间 | 普通图谱索引构建也要解析全部提交，成本与收益不匹配 |

## 验证

- Rust 集成测试覆盖作者时间过滤、单端区间、未来日期，以及作者时间与提交时间不一致的提交。
- 搜索分页在结果恰好满页时不得跳过下一条尚未处理的提交。
- 前端 `npm run build` / `npm run check` 与 release WebView2 实机验证覆盖日期输入、生效提示和重新打开后的区间保留。

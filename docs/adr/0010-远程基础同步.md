# ADR 0010：远程基础——fetch / pull --ff-only / push 与凭据边界

- 状态：已接受（2026-11-04 实现；门禁全绿，待 PR 与 GUI 实机验收）
- 日期：2026-11-04
- 影响范围：`crates/git-core/src/dto.rs`（WriteKind）、新增 `crates/git-write/src/remote.rs`、`remote/gate.rs` 与测试、`command.rs`、`execute.rs`、`gate.rs`、`src/app/useRemoteActions.tsx`、`GraphPane`、`src/shared/types.ts`、`src/i18n/locales/*`
- 触发依据：docs/11 批次 4；docs/06 N6；goal 规则「远程凭据不得被应用记录」

## 1. 背景

G6 批次 1/2/3 已覆盖本地提交、分支/标签与 stash。用户仍需要到终端执行 `git fetch` / `git pull` / `git push` 才能同步远程。docs/11 批次 4 明确范围为「fetch + pull --ff-only + push 基础」，完整 pull 与 merge/rebase 留待批次 5。

## 2. 决策

### 2.1 白名单与命令

`WriteKind` 新增 `Fetch`、`Pull`、`Push`。命令构造：

- Fetch：`git fetch`（使用当前分支上游 remote；无上游时由 Git 使用默认 remote）
- Pull：`git pull --ff-only`（只允许快进，不产生 merge commit）
- Push：`git push`（当前分支 → 上游；不推送 tags、不 `--all`、不 `--force`）

不提供 force push、prune、标签推送、多 remote 选择；需要时到终端执行。所有命令继续走 `run_git_output` 与命令日志。

### 2.2 凭据边界

- GitDock 内不出现密码/口令输入框，不读取、不落盘任何凭据。
- 执行器已注入 `GIT_TERMINAL_PROMPT=0`；HTTPS 依赖系统凭据管理器，SSH 依赖用户 key/agent。
- 认证失败时分类为 `outcomeRemoteAuthFailed`，提示用户：在内置终端完成一次 fetch/push 授权（终端交互不经过 GitDock），或配置系统凭据管理器 / SSH agent 后重试。
- 不在应用日志中记录 remote URL 中的凭据（URL 本身也不输出）。

### 2.3 Gate

| 操作 | 规则 | issue code |
|---|---|---|
| Fetch | 仓库至少配置一个 remote；bare 与中断态由通用前置拒绝 | gate_remote_missing |
| Pull | 当前处于本地分支（非 detached/unborn）；存在 upstream；工作区/索引完全干净 | gate_remote_detached / gate_remote_unborn / gate_remote_no_upstream / gate_remote_dirty_pull |
| Push | 当前处于本地分支；存在 upstream | gate_remote_detached / gate_remote_unborn / gate_remote_no_upstream |

- fetch 不要求工作区干净，因为只更新远程跟踪 refs。
- push 不要求工作区干净，因为推送的是已提交对象。
- pull 要求干净工作区/索引：首版只做 `--ff-only`，不在脏工作区上引入额外合并语义。
- upstream 由 `git rev-parse --abbrev-ref --symbolic-full-name @{u}` 探测；remote 列表由 `git remote` 探测。

### 2.4 执行与错误分类

- 成功：fetch / pull / push 返回 `Succeeded`，outcome 文案带当前分支/上游信息；写后刷新继续走 `execute_write` 的 generation 流程。
- 失败按 stderr 分类：
  - 认证失败：`authentication failed`、`could not read Username`、`terminal prompts disabled`、`Permission denied (publickey)` → `outcomeRemoteAuthFailed`。
  - pull 非快进：`Not possible to fast-forward` → `outcomePullNotFastForward`，提示先 fetch 并在终端 merge/rebase（批次 5）。
  - push 拒绝：`non-fast-forward`、`failed to push some refs`、`rejected` → `outcomePushRejected`，提示本应用不提供 force push。
  - 其他：`outcomeRemoteFailed`，保留 stderr。
- 网络超时：首版不设额外超时，命令执行期间 UI 显示进行中；失败由 Git stderr 呈现。

### 2.5 UI

- GraphPane 工具栏右侧新增紧凑「Fetch / Pull / Push」按钮组；按钮进行中显示对应「Fetching… / Pulling… / Pushing…」。
- 点击后先 Gate；Gate 拒绝在 GraphPane 顶部 banner 展示；执行失败同样展示 banner，不弹确认框（非破坏性操作）。
- 成功后调用既有 `onMutated`（toast + 快照 + 图谱刷新）；fetch 更新远程跟踪 refs，pull 更新工作区/HEAD，push 更新本地跟踪 refs。
- 按钮组使用 `flex-wrap`/`white-space: nowrap`，窄窗口下整组换行，不拆词。

## 3. 备选方案（未采纳）

| 方案 | 不采纳原因 |
|---|---|
| 应用内密码输入 | 违反凭据不得记录约束；需要安全存储与平台差异 |
| 首版 pull 允许 merge/rebase | 与批次 5 的 merge/rebase 状态机耦合；`--ff-only` 边界清晰、可恢复 |
| push 支持 `--force` | 破坏性远程操作，未获产品确认；终端可完成 |
| 自动 fetch 所有 remote | 多 remote/大仓库会产生不可控网络与耗时；首版跟随当前分支上游 |
| 手动选择 remote/refspec | 增加 UI 与协议面；首版以 upstream 为准 |

## 4. 后果

- `WriteKind` 19→22；新增 remote Gate 模块与前端动作 hook；不新增读命令，按钮在无 upstream 时由 Gate 返回明确错误。
- 用户可在应用内完成常规「fetch → pull 快进 → push」闭环；非快进/认证失败有明确去向（终端/凭据配置）。
- merge/rebase 与完整 pull、force push 仍不在本批。

## 5. 验收清单

1. 本地 bare remote：Fetch 后 `refs/remotes/origin/main` 与远端一致。
2. 本地落后远端：Pull --ff-only 后 HEAD 快进到远端，工作区文件更新。
3. 本地 ahead：Push 后 bare remote 的 main 指向本地提交。
4. 远端 ahead 且本地分叉：Push 被拒绝，远端不变，展示 `outcomePushRejected` 与 stderr。
5. 脏工作区：Pull Gate 拒绝 `gate_remote_dirty_pull`，不执行命令。
6. 无 remote / 无 upstream / detached HEAD：Fetch/Pull/Push 分别被 Gate 拒绝。
7. 认证失败（模拟 stderr 或手工）：分类为 `outcomeRemoteAuthFailed`，提示终端授权或凭据配置；应用日志不含凭据。
8. `npm run check` 全绿；触及文件行数合规。

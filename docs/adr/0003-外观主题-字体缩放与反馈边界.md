# ADR 0003：外观主题、字体缩放与反馈边界

- 状态：已接受
- 日期：2026-10-30
- 影响范围：`tauri.conf.json` 窗口主题、`src/styles/tokens.css` 与各样式片段、`SettingsDto.font_scale`、Tauri command seam、设置/关于界面、`docs/01-需求冻结.md`、`docs/03-技术架构.md`、`docs/06-GitDock后续需求与执行计划.md`
- 触发依据：`docs/06` 阶段 D 与 N2/N3/N4

## 1. 背景

阶段 D 需要在不引入自定义主题系统的前提下完成三件事：

1. 主题跟随 Windows 系统浅色/深色设置；
2. 提供整体字体放大、缩小、恢复默认的快捷键，显示缩放值并持久化；
3. 在设置/关于中显示版本号，并提供 Issue 入口；Issue 只预填应用版本与操作系统信息，用户检查后自行提交。

现有实现固定深色：`tauri.conf.json` 强制 `theme: "Dark"`，`tokens.css` 只定义深色令牌，部分样式片段直接写死颜色；WebView 没有全局缩放；设置中没有外观/关于区域，也没有版本展示或反馈入口。N4 要求快捷键由交互规范定义，但仓库尚无独立交互规范文件，因此本 ADR 同时冻结首版快捷键，后续规范变更时只改映射。

## 2. 决策

### 2.1 系统主题

- 首版只支持“跟随系统”，不提供应用内主题切换或自定义主题色。
- 移除 `tauri.conf.json` 中强制的 `theme: "Dark"`，让窗口标题栏与 WebView2 的 `prefers-color-scheme` 都跟随 Windows 应用主题。
- `tokens.css` 保留现有深色值，并在 `@media (prefers-color-scheme: light)` 中提供浅色语义令牌；样式片段只引用语义令牌，不再按主题写两套选择器。
- 终端面板外壳跟随主题；xterm 终端内容保持深色 ANSI 配色（背景、前景、光标、选区固定）。原因是 LazyGit/Shell 的 ANSI 调色板按深色背景调校，浅色背景会降低部分亮色可读性；终端属于独立的内容表面，不参与应用主题切换。该取舍记录在本 ADR，后续若要提供终端配色选项另立需求。
- 高对比度：补充 `@media (forced-colors: active)` 规则，让选中行、激活项和焦点态使用系统 `Highlight`/`CanvasText` 等颜色，不依赖低对比度背景色。

### 2.2 全局字体缩放

- 使用 Tauri WebView 的 `setZoom(scale)` 缩放整个 WebView，而不是逐组件改 `font-size`；这样图谱、详情、diff、暂存区、设置和终端外壳一起缩放。
- 缩放档位固定为 `75% / 80% / 90% / 100% / 110% / 125% / 150% / 175% / 200%`，默认 100%；到达边界后不再变化。
- 快捷键：
  - 放大：`Ctrl+=`、`Ctrl++`、`Ctrl+Shift+=`、`Ctrl+小键盘 +`；
  - 缩小：`Ctrl+-`、`Ctrl+小键盘 -`；
  - 恢复默认：`Ctrl+0`。
  - 仅在未按 Alt/Meta 时生效；使用窗口捕获阶段监听，终端聚焦时也由应用接管，不影响终端内的普通输入。
- 当前缩放值显示在状态栏右侧，并在设置“外观”区显示百分比和放大/缩小/恢复默认按钮。
- 持久化：`SettingsDto.font_scale: f64`，缺省 `1.0`；Rust 侧校验范围 `0.75..=2.0`。旧配置没有该字段时由 serde 默认值迁移，`schema_version` 不升级（新增字段向后兼容）。
- 快捷键改变缩放后立即应用并异步保存；保存失败只提示错误，不撤销已应用的缩放，避免界面跳动。

### 2.3 版本与 Issue 入口

- 设置弹窗增加“关于”区，显示应用版本、平台（如 `windows-x86_64`）和 Git 版本；数据来自既有 `app_info` command，不新增敏感信息读取。
- “反馈问题…”打开应用内弹框，标题与正文预填：
  - 应用版本、操作系统/架构、Git 版本；
  - 问题描述占位提示。
- 预填内容可编辑；提供“复制内容”和“打开 GitHub 新建 Issue”。只有用户点击后才打开浏览器，GitDock 不自动提交、不上传日志、不附加仓库路径。
- 打开网址通过受限 Tauri command：只接受应用内构造的固定仓库 Issue 地址，使用参数数组启动系统默认浏览器，不经过 shell；不提供通用 URL 打开能力。

## 3. 备选方案（未采纳）

| 方案 | 行为 | 不采纳原因 |
|---|---|---|
| 应用内主题选择（跟随系统/浅色/深色） | 增加设置项和持久化 | 超出 N2 首版范围；系统主题已能覆盖主要场景 |
| 逐组件调整 `font-size` 或 CSS `zoom` | 只放大文字/局部元素 | 无法保证图谱画布、diff 表格和弹窗一致缩放，容易布局错位 |
| 使用浏览器原生 Ctrl+/- 缩放 | 依赖 WebView2 默认行为 | 无法可靠显示当前值、持久化，也无法与终端快捷键统一 |
| 在应用内收集日志并上传 | 自动附加诊断 | 违反 N3“日志、仓库路径不自动上传”；首版只做预填与用户确认 |

## 4. 验收

| 编号 | Given / When / Then |
|---|---|
| D-1 | Given Windows 为深色 When 启动应用 Then 界面使用深色令牌，标题栏与 WebView 一致 |
| D-2 | Given Windows 为浅色 When 启动应用 Then 界面使用浅色令牌；运行中切换系统主题时界面无需重启即更新 |
| D-3 | Given 系统开启高对比度 When 查看图谱选中行、暂存区选中行与按钮 Then 选中/焦点态仍可辨认 |
| D-4 | Given 默认 100% When 按 `Ctrl+=` Then 缩放提升一档，状态栏与设置显示新百分比；重启后保持 |
| D-5 | Given 已放大 When 按 `Ctrl+-` Then 缩放降低一档；按 `Ctrl+0` 回到 100%；边界档位不越界 |
| D-6 | Given 焦点在终端或输入框 When 按缩放快捷键 Then 仍执行缩放，且不向终端/输入框发送字符 |
| D-7 | Given 打开设置 When 查看关于区 Then 显示应用版本、平台与 Git 版本 |
| D-8 | Given 打开反馈弹框 Then 预填内容只含版本、系统与 Git 信息；无日志路径、仓库路径；用户可编辑，未点击打开前不上传任何内容 |
| D-9 | Given 旧版 settings.json 没有 `font_scale` When 加载 Then 默认 100%，保存后写入新字段且不破坏既有配置 |

## 5. 后续

- 若产品后续提供独立交互规范并调整快捷键，只需修改前端映射与本节验收，不涉及持久化格式。
- 终端配色、自定义主题、日志导出与自动诊断不在本 ADR 范围，需另立需求/ADR。

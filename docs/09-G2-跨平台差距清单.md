# G2 跨平台准入 Spike：差距清单与建议

> 状态：2026-11-03 三路并行只读调查（Rust 侧 / 前端与打包 / CI 与依赖）汇总。
> 定位：docs/08 G2 任务的「缺口、适配工作量、发行阻塞与 go/no-go」交付物；CI 矩阵与 tauri.conf 改动随本清单落地，实机验证项见第 6 节。
> 约束：macOS 架构范围、Linux 发行版与首发包格式未获产品确认前，不对外宣称支持；本文所有「建议」均为可逆调查结论。

## 1. 总体结论

**倾向 go**。仓库平台耦合度低：显式平台分支全库仅 6-8 处且多数已带非 Windows 对侧；`git-core → git-read/git-write → graph-layout/refresh` 业务链路零 OS 分支；PTY（portable-pty）、文件监听（notify）、URL 打开（三分支已备）、目录 API（Tauri path）均天然跨平台。真正的工作量集中在四处：**终端 Shell 模式（硬编码 PowerShell）、外部工具探测（非 Windows 为空）、CI/发布矩阵（仅 Windows）、i18n 平台文案（14 个 key）**，与 docs/08 §3.3 PlatformAdapter 职责表一一对应，无架构级阻碍。

## 2. Rust 侧差距（crates/ + src-tauri/src/）

### A 级：非 Windows 上功能错误

| # | 位置 | 现状 | macOS/Linux 后果 | 方向 |
|---|---|---|---|---|
| A-1 | `src-tauri/src/app/terminal.rs:156-215` | Shell 模式从 `SystemRoot` 拼 PowerShell 绝对路径 + `-NoLogo -NoExit -Command` 与 UTF-8 编码参数，无 cfg 守卫 | Shell 终端报「未找到 PowerShell」完全不可用（LazyGit 模式不受影响） | G3 PlatformAdapter：`default_shell()` 读 `$SHELL`（兜底 zsh/bash），PowerShell 逻辑收进 Windows 分支 |
| A-2 | `src-tauri/src/app/config/tools.rs:32-36` | `#[cfg(not(windows))]` 探测返回空 Vec | 首启无内置 diff 工具，设置页「按当前系统探测」承诺落空 | 扩展探测表：macOS `/Applications` 形态、Linux PATH 查找（沿用只查路径不启进程的安全模式） |
| A-3 | `src-tauri/src/app/config/recent.rs:65-68` | `same_path` 按大小写不敏感折叠（Windows 语义） | Linux 大小写敏感 FS 上两个真实仓库被错误去重 | 路径比较进 adapter：Windows/macOS 折叠、Linux 精确 |
| A-4 | `src-tauri/src/app/terminal.rs:120-124, 284-298` | `kill` 仅直接子进程；80ms 轮询等 ConPTY 退出 | Unix 下 shell 内启动的孙进程可能残留孤儿 | G3：Unix `setsid`+`killpg`；Spike 实测项 |

### B 级：依赖与构建

| # | 位置 | 现状 | 影响 | 方向 |
|---|---|---|---|---|
| B-1 | `src-tauri/Cargo.toml:24-25`（ureq native-tls）+ `update.rs:46-55`（显式 NativeTls provider） | Linux 落到 openssl-sys | **Linux 编译需 `libssl-dev` + `pkg-config`**（macOS 用 Security.framework、Windows 用 schannel 均无碍） | 方案一（推荐，零代码）：Linux CI/打包环境装 libssl-dev；方案二：切 rustls（改 provider + 回归测试 + ADR） |
| B-2 | Tauri 2 框架前置 | Linux 需 webkit2gtk-4.1/GTK 系统库 | CI 与分发环境要求 | CI apt 步骤已落地（见第 5 节）；deb 依赖自动生成，AppImage 不含 WebKitGTK（运行时依赖系统库） |

### C 级：已平台中立（无需改，抽样确认）

`open_url` 三分支（external.rs:225-231，已是 adapter 雏形）；`hide_console`（git-core/process.rs，非 Windows no-op）；PTY 经 `native_pty_system()` 自适应；LazyGit 手工 PATH 扫描（含 `lazygit`/`lazygit.exe` 双候选，防目录劫持）；notify 的 inotify/kqueue/FSEvents 后端齐备；`strip_verbatim` 非 Windows no-op；`write_atomic` 的 Windows rename 兜底；`/dev/null` diff 参数在 Unix 原生成立；`home_dir` HOME→USERPROFILE 兜底；`GIT_TERMINAL_PROMPT=0` 注入；Git CLI 统一参数数组无 shell 包装；配置/日志/缓存目录全走 Tauri path API；`windows_subsystem` 非 Windows 安全忽略。业务 crate（git-read/git-write/graph-layout/refresh）零平台分支；`windows-sys`/`winapi`/`dunce` 均为按 target 自动排除的传递依赖。

## 5. CI 与发布链（本次落地）

- **ci.yml**：`verify` job 扩为 `windows-latest / ubuntu-22.04 / macos-latest` 三平台 matrix（`fail-fast: false`）；Linux 步骤 apt 安装 `libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev pkg-config`（libssl-dev 为本项目 ureq native-tls 特有硬需求）；三平台跑同一 `npm run check`（含 cargo test --workspace）。
- **release.yml**：`windows` 单 job 改为 `build` matrix（nsis / appimage,deb / dmg 三元组）+ `upload-artifact@v4` 中转 + 独立 `publish` job（needs build，download 后统一 `gh release create/upload --clobber`），保留版本核对与 prerelease 判定；step summary 补产物体积输出（满足 docs/08 §3.5「打包大小进发布检查表」）。
- runner 选择依据：`macos-latest`（Apple Silicon/arm64）对齐 docs/08 裁决点 2 推荐的「优先 Apple Silicon，Intel 延后」；`ubuntu-22.04` 取 glibc 2.35 基线（构建产物向上兼容 24.04+，反向不可）；Linux 双格式产出仅为 G5 选型供样，不构成支持承诺。
- 已知 CI 风险：① rust-cache 按平台分 key，Linux/macOS 首次无缓存时 `target/test-fixtures` 幂等问题曾出现过（64ae989 已修，多平台首跑仍需观察）；② 未加 `cargo --locked`（保持现状，若 lock 漂移显式失败再引入）；③ dmg 文件名带架构后缀（`_aarch64`），glob 用通配符覆盖。
- macOS 签名/公证：Spike 阶段不签（无证书，与 Windows 未签名现状对等）；实机验证需 `xattr -cr` 绕 Gatekeeper；Developer ID + 公证属 G4。

## 6. G2 验证清单（CI 通过后待实机/原生 runner 执行）

按 docs/08 G2 第 3 项：Git 读取/写入、SHA-256（如环境支持）、PTY/Shell（⚠ A-1 未修前 Shell 模式必失败，LazyGit 模式可测）、中文路径、文件监听（macOS FSEvents 合并语义重点）、设置迁移（旧 settings.json 无 language 字段默认值）、文件选择（Tauri dialog）、打开 URL、快捷键（⚠ F-1/F-2 未修前 ⌘ 不命中）、更新/Issue 入口（GitHub API 在 CI 出口 IP 限额风险）。

> 本轮在 Windows 开发环境完成：三路代码调查、CI workflow 文件与 tauri.conf 改动、本地门禁回归。**macOS/Linux dev/release 构建、安装与上述功能项均未执行**（需推送后 CI 首跑 + 实机），不把 CI 构建通过表述为平台支持。

## 9. 依赖与许可证现状

- 无 GPL/AGPL 阻塞（gix 而非 libgit2 从根规避）。全部直接依赖 MIT / MIT OR Apache-2.0 / Apache-2.0 OR MIT。
- 需在清单显式记录：`notify 8.2`（CC0-1.0）、传递依赖 `ring`（ISC/类 BoringSSL）、Linux 侧 OpenSSL（Apache-2.0）。
- 缺口：无 cargo-deny / deny.toml、无 npm license 工具（docs/08 §3.5 要求许可证清单进发布检查表，当前零覆盖）。建议 G3 最小方案：cargo-deny（licenses+advisories，秒级，跑 ubuntu job）。

## 10. go/no-go 建议

**go**，条件：① CI 三平台矩阵首跑通过（含 Linux apt 依赖正确性）；② 至少一个平台的实机安装与核心功能清单（第 6 节）通过；③ macOS 架构与 Linux 包格式两项产品确认完成（进入 G3 前不阻塞调查与可逆准备）。主要风险为 AppImage 的 WebKitGTK 跨发行版兼容（G5 议题）与 macOS 签名/公证的账号流程（G4 议题），均不阻塞 G2 准入结论。

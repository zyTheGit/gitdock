# V3 性能验证（分页 DTO / 虚拟列表 / 大 diff 响应预算）

- 阶段：阶段 0 V3 准入（技术终审固定：Tauri 2 + React + TS + @tanstack/react-virtual + react-diff-view + Shiki）
- 日期：2026-10-28
- 范围：只验证风险，不改架构；未修改 `crates/` 源码，未提交 Git。
- 结论：**PASS（有条件通过）**。分页 DTO、布局、大 diff 均满足建议预算，**未触发**否决条件「Tauri 在分页/大 diff 下无法满足响应预算」。条件见第 7 节（Tauri 壳未建、Shiki 未计入、多 lane DTO 待复核）。

## 2. 后端分页预算（5000 提交）

| 指标 | 实测（中位数） | 备注 |
| --- | --- | --- |
| 打开仓库 `GitReadModule::open` | **25.2ms** | 含一次 `git --version` 子进程 |
| `state()` | 8.7ms | refs + generation 指纹 |
| 首页 200 行（索引缓存冷） | **46.7ms** | 含 5000 提交遍历 + Kahn 拓扑排序 + 首页布局 |
| 首页 200 行（索引缓存热） | **12.5ms** | 生产常态（复用模块 + cache_dir） |
| 后续每页（第 2–25 页） | **12.1ms**，P95 17.1ms，max 20.7ms | 25 页合计 315.2ms |
| 200 行页 DTO JSON | **113.6KB**（中位 113.7KB） | commits 53.4KB + layout 59.9KB |
| 禁用索引缓存时的第 2 页 | 42.7ms | 每页重建索引的代价，必须避免 |

判定：打开 <500ms、每页 <150ms、200 行 DTO <200KB **均 PASS**，余量充足。

注意：`read_graph_page` 每次都调用 `build_index`。传入 `cache_dir` 时命中 JSON 缓存（约 12ms/页）；不传则每页重建（+30–40ms/5000 提交），且随提交数线性放大。生产实现必须复用 `GitReadModule` 并配置缓存目录。

对 25 页 × 200 行（共 5000 行）调用 `GraphLayoutModule::append`：

| 指标 | 实测 |

## 4. 大 diff 预算

方法：在 `target/v3/fixtures/perf`（临时夹具，非源码）HEAD 上追加两个提交：
- 提交 A：新增 `big.txt`（5000 行）、`single2000.txt`（2000 行）、`bin.dat`（512KB 二进制）、`huge.txt`（40000 行，约 2.4MB）；
- 提交 B：全量改写 `big.txt`（5000 行改动，patch 约 10000 行）。

| 场景 | 耗时（中位数） | patch 行数 / 截断 | JSON 大小 |
| --- | --- | --- | --- |
| commit 详情（A，4 文件） | 10.2ms | 文件列表完整 | 1.1KB |
| commit 详情（B，1 文件改写） | 3.9ms | — | — |
| 单文件 diff：5000 行新增 | **2.7ms** | 5000 行，`truncated=true` | **249.2KB** |
| 单文件 diff：5000 行改写 | 3.9ms | 5000 行，`truncated=true` | — |
| 单文件 diff：2000 行 | 2.3ms | 2003 行，未截断 | — |
| 二进制文件 `bin.dat` | — | `patch=null`，note「二进制文件…」 | — |
| 超大文本 `huge.txt`（2.4MB，超过 2MB 上限） | — | `too_large=true`，`patch=null` | — |
| `compare`（跨 5000 提交） | **75.0ms** | 文件列表 1，提交列表上限 200 | — |
| `compare_file_diff` | 4.5ms | 5000 行截断 | — |

截断常量核对：`MAX_PATCH_LINES=5000`、`MAX_DIFF_BYTES=2MB`（两者现下沉于 `crates/git-core/src/diff_limit.rs`，git-read / git-write 共用；核对时位于 `crates/git-read/src/diff.rs`）、`MAX_FILES=5000`、`MAX_LINE_COUNT_FILES=2000`（`crates/git-read/src/diff.rs`）。生成 patch 前先判 gitlink、blob 大小、二进制；patch 生成后按行截断并给出 note。

结论：**UI 侧永远不会拿到无上限 patch**——单文件 patch ≤5000 行或 `to_large/binary/gitlink` 结构化降级，文件列表 ≤5000 项。判定 PASS。

风险：5000 行 patch 的 JSON 为 **249.2KB**，超过 200KB。本任务 200KB 阈值针对 200 行分页 DTO，该值不影响 diff 时间预算；但若后续把 200KB 作为所有单响应上限，应把 diff 渲染范围降到约 2000–3000 行或分块传输，而不是提高 `MAX_PATCH_LINES`。

`compare` 的 75ms 是唯一接近单页预算（150ms）的接口：它需要为 base/compare 各构建一次全量可达集合；仓库规模再放大时应缓存或延后计算 `base_only/compare_only`。

## 5. 虚拟列表 POC（poc/v3）

锁定版本（写入 `package.json` + `package-lock.json`）：`@tanstack/react-virtual 3.14.23`、`react-diff-view 3.3.3`、`react 18.3.1`、`vite 5.4.20`、`typescript 5.6.3`。

测试条件：10000 行固定行高 28px，容器 900×600，`overscan=8`；滚动用 `scrollToIndex`；DOM 行数用 `[data-row]` 统计。

| 指标 | 实测（3 次中位数） | 说明 |
| --- | --- | --- |
| 首屏挂载（到 2 帧） | **51.8ms** | 29 个 DOM 行 |
| 滚动到中部（第 5000 行） | **26.8ms** | 37 个 DOM 行；60Hz 限帧模式 52.3ms（含 4 帧等待） |
| 滚动到末尾（第 9999 行） | **41.1ms** | 29 个 DOM 行；限帧模式 66.7ms |
| 回滚到顶部 | 6.2ms | 33–34ms（限帧） |
| react-diff-view 解析 5000 行 patch | 3.6ms | `parseDiff` |
| react-diff-view 渲染 5000 行 diff | **149.3ms** | **20006 个 DOM 节点**（约 4 节点/行） |
| react-diff-view 渲染 500 行 diff | 14.7ms | 2006 个 DOM 节点 |

包体积：`dist` JS **233.8KB（gzip 75.2KB）**，`dist` 总 233KB；`node_modules` 71MB（react-diff-view 2.1MB，react-virtual 76KB）。安装 77 个包，约 1 分钟。

端到端单文件 diff 预算：后端 2.7ms + 解析 3.6ms + 渲染 149.3ms ≈ **155.6ms < 300ms**，PASS（**未含 Shiki 高亮与 tokenize**）。

POC 过程中确认了锁定版本的 API 约束：`<Diff>` 必须同时传 `hunks` prop 且 children 为 `(hunks) => ...` 渲染函数，否则抛错。接入时按此写法封装。

## 6. 响应预算判定

| 预算项 | 阈值 | 实测 | 判定 |
| --- | --- | --- | --- |
| 打开仓库 | <500ms | 25.2ms | PASS |
| 首页/后续每页 200 行 | <150ms | 46.7ms（冷）/12.1ms（热） | PASS |
| 200 行 DTO JSON | <200KB | 113.6KB | PASS |
| 5000 行布局 append | 无硬阈值 | 总 8.4ms | PASS |
| 单文件 diff（后端） | <300ms | 2.7–3.9ms | PASS |
| 单文件 diff（后端+解析+渲染） | <300ms | ≈155.6ms（不含 Shiki） | PASS（有条件） |
| patch 上限 | ≤5000 行 / 2MB | 严格截断，结构化降级 | PASS |
| compare | <300ms | 75.0ms | PASS |

**否决条件结论：未触发。** 分页、布局、大 diff 三条路径在 5000 提交/5000 行变更规模下都有 3–10 倍以上余量，唯一接近阈值的是 compare（75ms）与 5000 行 diff 渲染（149ms）。

## 7. 条件与后续风险

1. **Tauri 壳未建**：本报告是后端 + 浏览器渲染层近似。IPC 序列化/传输开销、WebView2 与 Chrome 的差异、Windows 高 DPI、Shiki tokenize 均未实测，需在 M1 后补真机复测。分页 DTO 113.6KB、diff 249.2KB 可作为 IPC 载荷上界参考。
2. **多 lane 布局 DTO 膨胀风险**：5000 提交线性夹具只有 1 条 lane，layout DTO 59.9KB 主要由 `before_lanes/after_lanes` 构成。若真实仓库 20+ lane，每行数组可达数百字节，200 行 DTO 可能突破 200KB。届时应**缩小 DTO**（改为发送 lane 增量/线段，而非每行完整 before/after 快照），不要削减 commits 字段；M1 需用 forked/密集合并夹具复核。
3. **diff 渲染节点过多**：5000 行 diff 产生约 2 万 DOM 节点，Shiki 全量高亮会进一步放大。建议 diff 面板保持后端 5000 行截断 + 前端按 2000–3000 行分块/折叠，Shiki 只 token 化可视窗口；不要提高 `MAX_PATCH_LINES`。
4. **索引缓存必须启用**：不传 `cache_dir` 时每页重建索引（5000 提交 +30–40ms，线性增长）。这是分页预算的前置条件。
5. `compare` 的 75ms 随仓库规模增长（两遍可达集合遍历），大仓库需缓存或延迟统计左右差异数。

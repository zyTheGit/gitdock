# 阶段 0 验证准入结论

> 日期：2026-10-28。依据 `docs/02-选型终审.md`，V1–V4 只验证既定选型的风险，不重新竞选方案。

## 结论

**有条件通过，未触发否决条件。** 可以进入阶段 1；下列条件必须在对应里程碑完成前落实，否则视为未满足准入。

## 附加条件

1. **M1 后真机复测**：V3 的数值来自后端与浏览器渲染近似，Tauri IPC + WebView2 需在 M1 完成后复测分页与 diff 预算。
2. **DTO 收敛**：多 lane 仓库的行 DTO 会膨胀，前端只保留渲染所需字段；diff JSON 249KB 接近上限，需按窗口请求。
3. **必须启用索引缓存**：否则每页增加 30–40ms。
4. **diff 面板窗口化**：Shiki 高亮未计入 V3 预算，仅高亮可视行。
5. **Write Gate 三合一**：标记文件（`--git-path` 后按 `--show-toplevel` 解析）+ porcelain v2 `u` 行 + bare 预判；`AUTO_MERGE` 不得作为标记。
6. **cherry-pick 与 hook**：一次性 cherry-pick 只触发 prepare-commit-msg / post-commit，pre-commit 与 commit-msg 被绕过；UI 文案不得承诺钩子必跑，禁止用 `--no-commit` 两步法规避。
7. **空 pick**：退出码 1 且 porcelain 接近干净态，必须识别为“需用户决策（跳过/放弃/退出）”，禁止自动 `--skip` / `--quit`。
8. **switch 预判占用**：调用前用 `worktree list --porcelain` 检查分支占用；始终 `--no-guess`，禁止 `-f` / `--ignore-other-worktrees`。
9. **Git 版本下限**：建议 >= 2.40；启动检测，低于下限时只读可用、写操作禁用并提示升级。

## 遗留风险

- V2 发现 `GitReadModule::open` 会执行 `git --version` 子进程（只读探测），与“只读模块不启动子进程”的严格表述不符；不构成正确性问题，列入 P1 收敛。
- gix 启用但未使用的 `worktree-mutation` / `status` feature 待裁剪。
- 索引缓存按 generation 命名且无淘汰，长期使用会累积文件。
- generation 为内容指纹而非单调序号，状态完全回退时旧 cursor 会复活（内容一致，风险可接受）。
- SHA-256 仅单一 2 提交夹具；shallow 仅验证 HEAD 视图。
- V4 未覆盖：Git < 2.40、`core.hooksPath`/`.cmd` 钩子、非 ASCII 路径、submodule/LFS/autocrlf=true。

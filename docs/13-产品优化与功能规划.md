# GitDock 产品优化与功能扩展规划（任务总纲）

- 更新日期：2026-11-20
- 适用基线：`v0.2.7`（含 Stash 时间戳修正、错误横幅可关闭与残留清理、README 口径对齐）
- 文档定位：面向**多智能体 / 多模型分派执行**的总调度文档。每个可执行任务已拆分为 `docs/tasks/Txx-*.md` 独立任务卡，分派时只需把「根目录 `AGENTS.md` + 对应任务卡」交给执行模型即可独立推进。

## 1. 通用执行契约（所有任务卡强制继承）

任何模型在执行本规划下的任意任务前，必须先阅读仓库根目录 `AGENTS.md` 与 `docs/03-技术架构.md`，并严格遵守以下硬规则：

1. **架构边界不可越界**
   - 依赖方向：`git-core`（零内部依赖）← `git-read` / `graph-layout` / `git-write` / `refresh` ← `src-tauri`；跨进程只走 Tauri command seam。
   - `git-read` 保持纯 `gix` 只读，禁止起子进程与写文件（须通过 `crates/git-read/tests/v2_readonly.rs` 静态守卫）。
   - `git-write` 是唯一仓库写通道，新增写能力必须走 `WriteKind` 白名单 + Gate 校验 + 写互斥锁 + 参数数组执行，绝不拼接 shell 字符串。
   - 破坏性操作与历史改写（丢弃改动、hard reset、force 类、rebase 等）必须配专门二次确认与恢复指引（或不可恢复警告）。
   - 前端只用语义 CSS 令牌（`src/styles/tokens.css`），不写死浅/深色；所有 UI 可见文案必须双语同步 `src/i18n/locales/zh-CN/` 与 `en/`。
2. **ADR 先行原则**
   - 凡涉及新增 `WriteKind`、修改跨进程 DTO、新增 Tauri command、修改 `docs/03-技术架构.md` 既有不变量的任务，**必须先在 `docs/adr/` 新增或修订对应 ADR**（从 `0026` 起编号），再动手写代码，并同步更新 `docs/03-技术架构.md`。
3. **文件行数硬规则（物理行 `wc -l`）**
   - 所有源码与测试文件单文件上限 **600 行**，新文件按 **400 行以内**规划。
   - 修改已超 600 行的存量文件时，行数**只减不增**。
   - 交付前必须自查所有触及文件的行数，超限当场拆分。
4. **交付验证与边界**
   - 前端改动必跑 `npm run build`（含 `tsc --noEmit`）；所有任务收尾必跑全量 `npm run check`（含版本号、i18n、IPC 契约、构建、`cargo fmt`、`cargo clippy -D warnings`、`cargo test --workspace`）。
   - 涉及窗口、终端、CSP 或外部进程交互的改动，须补充 release 构建运行验证。
   - **默认不自动 `git commit`、不打 tag、不 `git push`、不改版本号**，除非用户明确指令。

## 2. 分波次路线与依赖关系

```text
Wave 0（工程前置，强烈建议最先执行）
  └── T01 工程治理与超限文件拆分（解除 dto.rs / App.tsx / 测试文件行数瓶颈 + npm 许可证门禁）
        │
        ├── Wave 1（体验优化，彼此文件边界隔离，可并行）
        │     ├── T02 侧边栏重构与远程分支导航
        │     ├── T03 暂存区提交流程与文件右键增强
        │     ├── T04 详情与 Diff 浏览及快捷键增强
        │     └── T05 文件树视图切换
        │
        ├── Wave 2（P0 核心 Git 写能力，须先写 ADR，建议按序合并避免 dto/gate 冲突）
        │     ├── T06 工作区改动丢弃与未跟踪清理（依赖 T01）
        │     ├── T07 Hunk 与行级暂存（依赖 T01，建议在 T06 后）
        │     ├── T08 远端跟踪分支检出与上游同步增强（依赖 T01、T02）
        │     └── T09 本地回退 Reset 与 Reflog 恢复视图（依赖 T01）
        │
        └── Wave 3（P1–P2 差异化与进阶能力）
              ├── T10 Stash 内容预览与工作区对比增强（依赖 T01）
              ├── T11 单文件历史与 Git Blame 追溯（依赖 T01）
              └── T12 多仓库标签页 / 轻量冲突辅助 / Worktree 管理（拆为 12A/12B/12C 独立推进）
```

> **并行调度建议**：
> - 同一时刻，**只让 1 个模型修改 `crates/git-core` 或 `src/App.tsx`**，避免契约与主壳合并冲突。
> - Wave 1 的 `T02` / `T03` / `T04` / `T05` 主要落在各自 feature 目录，在 `T01` 拆出 `App.tsx` 装配层后非常适合多模型并行。
> - Wave 2 的 `T06`–`T09` 均涉及 `WriteKind` 与 `git-write`，建议逐项在独立分支完成后合入，再开下一项。

## 4. 分派给其他模型的标准提示词模板

复制以下模板并替换 `<Txx>` 路径即可直接发给其他模型执行：

```text
请先阅读仓库根目录的 AGENTS.md、docs/03-技术架构.md、docs/13-产品优化与功能规划.md，以及本次要执行的任务卡 docs/tasks/<Txx-*.md>。

严格按任务卡的「范围与边界」「关键设计约束」「分步实施指引」完成开发：
1. 若任务卡标注「需 ADR：是」，先按约定在 docs/adr/ 新增或修订 ADR 并同步 docs/03-技术架构.md，再修改代码。
2. 严守架构边界与依赖方向；所有触及文件最终物理行数必须 ≤ 600 行（新文件 ≤ 400 行）。
3. 所有新增 UI 文案必须同步 zh-CN 与 en 两套 i18n 资源，只使用 CSS 语义令牌。
4. 完成后运行 npm run check（如受环境限制可分步跑 npm run build 与 node scripts/verify.mjs --skip-build），并逐条对照任务卡的验收标准汇报结果与所有触及文件行数。
5. 未经我明确要求，不要执行 git commit / tag / push，不要修改版本号。
```

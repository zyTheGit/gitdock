## 二、可开发需求（B 类，建议按序推进）

### R1 标签远程删除（P0，建议下一项）

- **用户场景**：删除本地标签时同时删除 origin 上的同名标签；无远程同名标签时只删本地。
- **价值**：与 ADR-0022 的分支远程删除对齐，补齐「本地和远程删除」能力矩阵。
- **范围**：
  - `WriteKind` 新增 `delete_tag_remote`（snake_case），请求复用 `branch` 字段。
  - Gate：`remote_count > 0`；标签存在性用本地 `refs/tags` + 远程跟踪缓存/远端执行失败兜底。
  - 两段式执行：先 `git tag -d <tag>`，成功后 `git push origin --delete <tag>`。
  - 菜单新增「删除本地和远程标签」；确认框标题/警告/失败恢复与分支远程删除一致。
  - ADR-0022 增补标签章节；GUI 验收清单补条目。
- **不做**：force push、`git branch -D`、多 remote 选择、远程引用实时 ls-remote（保持本地缓存 + 执行失败兜底）。
- **验收标准**：有远程同名标签时菜单项可用；删除后本地与远程标签均消失；远程失败提示「本地已删除，远程删除失败」并保留对话框。
- **下一步**：建 `feature/tag-remote-delete`，复用 ADR-0022 的 Gate/execute 结构。

### R2 npm 许可证与供应链门禁（P1）

- **用户场景**：CI 能自动拦截 GPL 类阻塞许可证与新增未登记依赖，避免发布后才暴露合规问题。
- **价值**：补齐 Rust 已有 `deny.toml` + licenses job 的 npm 侧空缺。
- **范围**：选型（`license-checker` JSON 输出 / 自写脚本读 `package-lock.json` 白名单）；接入 `npm run check` 与 CI；登记 CC0-1.0 等特殊许可证口径与 Rust 一致。
- **验收标准**：本地 `npm run check` 与三平台 CI 均对 npm 依赖做许可证校验；白名单外许可证会被拒绝。
- **下一步**：先给选型对比（是否新增 devDependency、是否进 check 七项），确认后实施。

### R3 文档口径收口（P2）

- **用户场景**：架构文档准确反映 G6 与收口期新增的写操作与模块边界，避免后续开发按过期结构改造。
- **范围**：`docs/03-技术架构.md` 补 G6 新增写操作清单与 `branch / tag / stash / remote / history / commit / interruption_outcome` 等模块职责；核对 `docs/08`、`docs/11` 的收口注记与 ADR-0022 链接。
- **不做**：不改动架构本身；不写代码。
- **验收标准**：`docs/03` 的写操作白名单、Gate 分派、模块依赖与代码一致；`docs/05` §0.1 无需再提示该缺口。

### R6 `dto.rs` 拆分（独立排期，P3）

- **用户场景**：契约文件长期超过 600 行上限，写请求 DTO 持续膨胀（771 行）。
- **范围**：按 OID / 写请求 DTO / 错误码 / cursor / 只读 DTO 拆分；纯移动，不改字段与序列化。
- **风险**：引用面广（git-core / git-read / git-write / src-tauri），需一次性改完所有 import；建议单独排期，不与功能需求并行。

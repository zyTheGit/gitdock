# GitDock 后续需求与执行计划

> 状态：阶段 A（技术 Spike，go）与阶段 B（内置终端工作区）已完成；阶段 C 暂存区已实现，分支切换 dirty 策略待产品裁决（ADR 0002）。产品代号：GitDock，Git Graph 作为图谱模块名称保留。

## 1. 产品定位

GitDock 是可扩展的 Git 桌面工作台。图谱用于理解提交历史；原生界面承接高频 Git 操作；可选的内置终端工作区用于在当前仓库上下文中运行 LazyGit 或 Shell，覆盖尚未实现的操作，减少在 GitDock、IDE 与独立终端之间切换。

通用插件系统暂不作为本期实现范围。先稳定仓库会话、Git 操作与终端集成的接口，再设计插件权限、分发和兼容策略。

## 3. 产品与技术方案

### 3.1 工作区布局

主界面维持图谱、详情、搜索和对比布局。增加终端面板入口与快捷键，面板默认收起，打开后停靠在底部，可拖动高度并记住尺寸。面板内可选择 LazyGit 或 Shell。关闭面板与结束进程是不同动作，退出/切仓库时须明确处理正在运行的进程。

### 3.2 模块接口建议

- `TerminalWorkspace`：前端只传递仓库会话标识与启动模式，不传任意工作目录；负责打开/关闭、尺寸、焦点、进程状态与退出确认。
- `TerminalHost`：Rust 侧拥有 PTY 和子进程生命周期，工作目录只能来自当前已打开仓库；输出通过有界事件流传输，支持窗口尺寸变化、输入和信号/退出。
- `RepositorySession`：继续作为当前仓库身份的唯一来源。终端进程关闭或收到文件系统变更后，触发既有刷新协调器，不另造一套刷新状态。
- `LazyGitAdapter`：检查配置的可执行文件并以 argv 启动；支持用户选择路径。启动环境清理会导致错误行为的继承变量，并设置终端尺寸/颜色能力。
- 安全能力：默认只允许终端访问当前仓库目录；不开放任意路径启动或由 WebView 直接 spawn 进程。终端命令具有与用户本人 Shell 相同的本机权限，需在界面明确说明。

在 Spike 前比较两条前端方案：WebView 内终端模拟器 + Rust PTY；原生终端子窗口/独立窗口。首选内嵌方案，只有在 Windows 输入法、焦点、快捷键、ANSI/Unicode、resize、进程回收或体积不达标时才评估独立终端回退。不得仅依据开发模式判断，需测 release 包。

### 3.3 暂存区与分支切换

暂存区按 `HEAD → Index → Worktree` 展示状态。文件行显示 staged/unstaged 两类状态；用户可查看 staged diff 与 unstaged diff，并分别 stage、unstage。第一版不提供部分行暂存、交互式暂存或自动 stash。

切换分支时先读取状态并在确认 UI 中列出受影响文件。不得自动 stash、reset 或丢弃改动。若 Git 能安全保留改动，可由用户显式确认后尝试 `git switch`；若目标分支会覆盖文件或 Git 拒绝，保留原状态并展示错误与建议。需更新 MVP 原有“所有 dirty 一律拒绝”的 Gate 决策与验收，避免旧规则和新需求冲突。

> 决策状态（2026-10-30）：需求与 ADR 已修订，方案见 `docs/adr/0002-暂存区与-dirty-分支切换策略.md`；推荐“显式确认 + 由 Git 判定”。产品裁决前，切换分支继续保持“dirty 一律拒绝”，不实现依赖新策略的行为；暂存区部分不受影响。

## 4. 分阶段任务拆分

### 阶段 A：产品/技术准入 Spike（不改产品功能）

1. 比较至少两种 Windows 内嵌终端/PTY 方案，记录维护状态、许可、输入法/Unicode/ANSI、resize、焦点与快捷键、崩溃/退出回收、体积。
2. 用 LazyGit 当前稳定版作为外部可执行程序做启动与交互验证；记录 PATH/自定义路径、启动失败、进程退出和仓库变更检测。
3. 以当前 release 安装包为基线记录 MSI 与 NSIS 大小，产出 Spike 包并量化差值。
4. 提交结论：推荐方案、否决项、风险、体积是否满足 10 MiB 门槛；未过门槛时给出不捆绑 LazyGit/外置终端等方案。

完成标准：报告包含可复现步骤、版本/许可证来源、尺寸实测和明确的 go/no-go 建议；本阶段不新增正式 UI 或依赖到主应用。

> 阶段 A 状态（2026-10-30）：已完成，结论 go。报告见 `docs/verification/阶段A-终端Spike.md`；推荐 `portable-pty 0.9.0` + `xterm.js 6.0.0`，MSI +152 KiB / NSIS +136 KiB。Spike 实现暂存在 `spike/terminal` 分支，按阶段 B 验收后再视为正式功能。

### 阶段 B：工作区外壳与同步

1. 终端面板布局、折叠/高度持久化、焦点和快捷键。
2. PTY host 和前端终端模拟器；命令仅以当前仓库目录启动。
3. LazyGit/Shell 选择、可执行文件配置、缺失/启动错误展示。
4. PTY 生命周期、关闭/切仓库确认、退出码和日志脱敏。
5. 终端操作后的仓库状态与图谱刷新，复用现有 generation/refresh coordinator。

完成标准：可在同一窗口当前仓库启动 LazyGit 和 Shell；两者修改仓库后 GitDock 收敛到最新状态；切仓库和退出不会留下孤儿进程；无 LazyGit 时其它主功能可用。

> 阶段 B 状态（2026-10-30）：已完成，提交 `fcdbc4c`。验收实测：LazyGit 0.66.1 与 PowerShell 均可在当前仓库启动并退出（退出码 0）；Shell 中提交后图谱自动刷新；切仓库自动结束旧会话并收起面板；优雅关闭应用后无 `git-graph-app.exe`/Shell 残留；LazyGit 缺失时显示安装与设置指引且 Shell 不受影响；安装包 MSI 4.92 MiB / NSIS 3.41 MiB（终端增量 MSI +152 KiB / NSIS +136 KiB）。未完成项：真实中文 IME 候选窗与多屏 DPI resize 的人工逐项验证。详见 `docs/05-交接文档.md` 8.2。

### 阶段 C：高频原生 Git 操作

1. 暂存/未暂存状态模型与文件列表。
2. staged/unstaged 文件 diff。
3. 单文件 stage/unstage 与批量 stage/unstage；不支持部分行暂存。
4. 暂存区写操作 Gate、结果状态机与刷新。
5. 分支切换对 dirty/staged 文件的可保留与覆盖冲突分流；始终不自动 stash/丢弃。

完成标准：暂存区状态与 Git CLI 一致；任何失败都保留用户改动并提供可理解诊断；原有 F1–F8 可靠性不变量持续成立。

### 阶段 D：产品完善

1. 系统主题跟随与高对比度/控件可读性检查。
2. 全局字体缩放与快捷键冲突处理。
3. 关于页版本展示与 Issue 入口，预填非敏感环境信息并由用户确认后提交。
4. 安装包体积、升级兼容、LazyGit 配置迁移与文档。

## 5. 本期明确不纳入

- 将 LazyGit 二进制捆绑进安装包或静默下载更新。
- 通用第三方插件市场、任意插件代码执行 API。
- 自动 stash、reset、clean、冲突自动解决或静默丢弃数据。
- 在终端内自动解析/拦截所有 Git 命令并推断其语义。
- fetch/pull/push、merge/rebase 等远程与历史改写操作的原生界面（另立阶段与 ADR）。

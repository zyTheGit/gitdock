# GitDock 产品收口与交互优化需求拆分

- 更新日期：2026-11-27
- 适用基线：`v0.2.8` / `main`
- 状态：T13–T22 已实现并通过主智能体集成验收；用户实机验收仍待补
- 目标：冻结新增 Git 写能力一个版本周期，优先降低默认界面复杂度、补齐核心工作流发现性、统一操作反馈与恢复体验。

---

## 1. 产品目标与非目标

### 目标

1. 仓库、工作区、远程同步等入口职责单一，消除重复动作。
2. 保留图谱与 Base / Compare 双槽的核心可发现性，降低常驻信息密度。
3. 补齐窄窗口引用访问、常用对比方案、操作恢复入口。
4. 在统一操作目录之后提供命令面板，避免把重复入口简单搬进搜索框。

### 非目标

- 不删除已有 Git 能力，不新增 `WriteKind`、Tauri command 或跨进程 DTO。
- 不改变 Gate、写互斥锁、刷新 generation 和危险操作确认语义。
- 不恢复已移除的 diff 字号控件、原生 Windows/Linux 菜单或搜索历史。
- 不实现 3+ ref 对比、多 Remote、交互式 rebase、force push、插件 API、团队协作或 AI 功能。

---

## 2. 通用执行契约

所有任务卡继承仓库根目录 `AGENTS.md`、`docs/03-技术架构.md` 与 `docs/13-产品优化与功能规划.md` 的约束：

1. 纯前端任务不得直接执行 Git 命令或解析 `.git` 内容。
2. 所有新增 UI 文案同步 `zh-CN` / `en`，只使用 CSS 语义令牌。
3. 不增加装饰动画；加载反馈仅使用功能性 spinner 或即时状态文本。
4. 异步动作必须有 busy / disabled 与同步防重入保护。
5. 源码与测试单文件不超过 600 行，新文件按 400 行以内规划；修改已超限文件时行数只减不增。
6. 前端改动运行 `npm run build`，任务收尾运行 `npm run check`。
7. 涉及布局、弹层、菜单和键盘交互的任务，必须使用 release GUI 实机验证，不能只以 Vite 或类型检查作为验收。
8. 未经用户明确要求，不提交、不打 tag、不推送、不改版本号。
9. 每批实现完成后同步 `docs/05-交接文档.md`。
10. 当前任务均不需要 ADR；若实施范围扩展到 DTO、Tauri command、`WriteKind` 或既有架构不变量，必须先停止并按仓库规则新增 ADR。

## 3. 波次与依赖

```text
Wave 0：产品口径
  └── T13 产品范围与验收口径对齐

Wave 1：首屏精简（文件边界可并行）
  ├── T14 全局导航与工作区入口收敛
  ├── T15 远程同步工具栏收口
  ├── T16 CompareBar 紧凑化
  └── T17 Worktree 自适应展示

Wave 2：核心工作流补强
  ├── T18 窄窗口引用入口（依赖 T14）
  ├── T19 常用对比方案（依赖 T16）
  └── T20 操作反馈与恢复入口统一（依赖 T14、T15）

Wave 3：操作发现性
  ├── T21 统一操作目录（依赖 T14–T20）
  └── T22 命令面板（依赖 T21）
```

并行约束：

- T14–T17 可由不同执行者并行，但同一时刻只能有一个执行者修改 `src/app/TopBar.tsx` 或 `src/app/AppShell.tsx`。
- T18 必须等 T14 完成后再改顶栏，避免入口覆盖。
- T19 必须等 T16 完成后再扩展 CompareBar，避免重复重构同一组件。
- T20 依赖 T14 / T15 的最终入口和反馈位置，建议在二者合并后实施。
- T21 汇总前序任务的最终操作集合；T22 只消费 T21，不自行拼装命令。

## 5. 推荐实施顺序

### 第一轮：低风险收口

1. T13：先统一产品范围与验收口径。
2. T14：合并仓库入口，删除重复暂存入口。
3. T15：收口远程同步工具栏。
4. 合并后运行一次 release GUI 回归，确认顶栏、标签栏和图谱工具栏没有布局回退。

### 第二轮：降低常驻密度

1. T16：CompareBar 一行化。
2. T17：单 Worktree 紧凑展示。
3. 验证 1280×800、窄窗口、高缩放和浅/深色。

### 第三轮：补强核心工作流

1. T18：窄窗口引用入口。
2. T19：常用对比方案。
3. T20：统一操作反馈与恢复入口。

### 第四轮：提升操作发现性

1. T21：建立统一操作目录。
2. T22：在目录之上实现命令面板。
3. 确认命令面板只复用既有动作，不绕过 Gate 或产生第二套执行逻辑。

## 6. 完成定义

每个任务只有在以下条件全部满足时才算完成：

- 任务卡范围内的功能已实现，非目标未被带入。
- 验收标准逐条通过，并有 release GUI 证据或明确的环境限制说明。
- `npm run build` 与 `npm run check` 通过。
- 所有触及文件满足行数硬规则。
- 中英文 i18n 完整，键盘路径与 `aria` 属性可用。
- 未修改版本号，未执行提交、tag 或推送。
- 当前批次已同步到 `docs/05-交接文档.md`。

## 7. 明确暂缓项

- 3+ ref 同时对比。
- 多 Remote 管理。
- 交互式 rebase。
- Force push。
- 跟随移动 ref 的对比方案（T19 首版只保存 OID 快照）。
- 插件 API、团队协作、GitHub 集成与 AI 功能。

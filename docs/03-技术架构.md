# GitDock 技术架构

## 架构原则

系统以 GitReadModule / GraphLayoutModule / GitWriteModule / RefreshCoordinator 四个核心深模块组织，另有 TerminalHost、多仓库会话注册表（RepoRegistry）与外观设置等受限能力模块。每个模块只暴露调用方真正需要的 interface，把 Git 格式、并发、布局和进程细节留在 implementation 内，确保调用方获得足够 leverage，变更也集中在同一处保持 locality。

```text
React / Tauri WebView
  WorkspaceController ────────> GitReadModule ──> gix
         │                            │
         │                            └──> GraphLayoutModule
         │
         ├──────────────────────> GitWriteModule ──> Git CLI
         │                                  │
         └──────────────────────> RefreshCoordinator
```

## 模块与 interface

### GitReadModule

**职责**：将仓库、refs、对象格式、遍历与 diff 的复杂性封装为只读 DTO。

**interface**：`open_repository(path)`、`read_graph_page(query, cursor, limit)`、`read_commit(oid)`、`read_file_history(path, oid_or_scope, cursor, limit)`、`read_file_blame(oid, path)`、`read_reflog(limit)`、`read_stashes()`、`read_stash_detail(oid)`、`read_stash_file_diff(oid, path, ignore_whitespace)`、`compare_sides(base, compare, path_filter, two_dot)`、`compare_sides_file_diff(base, compare, path, two_dot, ignore_whitespace)`（两侧接受提交 OID 或保留字 `worktree`）、`search(query, scope, cursor)`、`export_tree(oid, sink)`。

**不变量**：所有 OID 使用仓库自身对象格式；页面按拓扑序；cursor 是不透明 continuation token，不允许 offset；返回值包含读取时的 repository generation；`worktree` 只作为对比槽位的保留字由 `git-read` 解释，工作区侧的 `base`/`compare` 是占位 OID，真实方向只看 `worktree_side`（ADR-0030）。

**implementation**：gix 读取、ref peel、commit walk、diff 元数据与二进制降级、目录树导出（`TreeSink` 回调，落盘由 app 层 `dir_diff` 承担，ADR-0025）、单文件历史（按树条目 OID 剪枝，不做内容 diff）与行级 Blame（沿首父链逐行归因，ADR-0031）、`HEAD` reflog 只读读取（纯 gix，最新在前，默认 200 条、上限 1000，无 reflog 时返回空，ADR-0029）、本地分支上游 ahead/behind 计数（有界 merge-base walk，超限返回缺省，ADR-0028）、stash 快照预览（tracked 改动取第 1 父树，`stash -u` 的未跟踪文件取第 3 父树，按路径合并、上限 2000 文件）与工作区对比（以目标提交树为 `head_tree` 跑 gix status，取路径并集后只读比对提交树与磁盘文件，纯 gix 无子进程）、可选的忽略空白统一 diff 生成与图片预览 data URI（ADR-0030）、提交签名标注（只读 `gpgsig` / `gpgsig-sha256` 附加头首行，得 `gpg` / `ssh` / `x509` / `unknown`；不验签、不返回签名体，ADR-0034）。这里是唯一了解 Git 对象结构的模块。

### GraphLayoutModule

**职责**：把按拓扑序的 `GraphPage` 映射为稳定 lane、边和待连接边。

**interface**：`append(page)` 返回可渲染增量，`reset(view_key)` 建立独立布局状态。

**不变量**：同一 `view_key` 生命周期内既有提交 lane 不改变；缺失父节点使用 pending edge；布局计算不访问文件系统、不执行 Git。

**implementation**：轨道分配、父子边路径、可视窗口裁剪。它是纯函数核心，适合由其他智能体独立验证。

### GitWriteModule

**职责**：把有限写操作封装为显式状态机，而非向前端暴露通用命令执行；Git 配置读写（白名单键、用户级/项目级两层）也经由本模块收敛，app 层不设第三个 Git 交互入口。

**interface**：`validate(operation)`、`execute(operation)`、`inspect_interruption()`、`staging_status()`、`staging_file_diff(path, staged, ignore_whitespace)`、`list_worktrees()`、`read_commit_template()`、`read_git_config(repo)`、`save_git_config(scope, repo, entries)`。

**不变量**：仅接受白名单操作；命令以参数数组启动；每次执行前运行 Gate；每次非零退出后重新读取操作态；绝不自动 abort / quit；切换分支绝不自动 stash / reset / clean，dirty 时 Gate 返回不阻断的 warning 与受影响路径，由 `git switch --no-guess` 判定覆盖风险；暂存操作只接受当前 `git status` 中存在的路径；hunk 级暂存 / 取消暂存 / 丢弃的补丁一律由服务端从实时 diff 重新生成（前端只给 `path` + 0 起始 `hunk_index`，从不提供 patch 文本），超出「实时 diff 块数」的序号被拒绝而不是把补丁打歪（ADR-0027）；行级暂存仍不提供；丢弃改动同样只作用于当前 status 的未暂存/未跟踪路径，且不执行 `git clean`、不碰 ignored 文件与 `.git`（ADR-0026）；重置必须显式给出 soft / mixed / hard 模式、目标必须解析为 commit，`--hard` 属强破坏性操作：Gate 返回受影响路径与 `reset_hard_destructive` warning，前端必须用强破坏性确认（已提交历史可经 Reflog 找回、未提交改动不可恢复），reflog 视图只读、应用永不 expire / gc reflog（ADR-0029）；冲突解决只接受实时 status 中处于 conflicted 的单一路径，checkout 只覆盖工作区、add 才标记已解决，可在中断态内执行但仍不自动 continue / abort，`mark_conflict_resolved` 对文件内残留的冲突标记只返回非阻断 warning（ADR-0033）；暂存与 diff 的读取使用 `GIT_OPTIONAL_LOCKS=0`，避免监听自激；配置读写只开放白名单键且值经校验（控制字符/长度/邮箱/分支名字符集），项目级（`--local`）配置写与其他写操作共用同一互斥锁，用户级配置写不触碰仓库、无需持锁（见 ADR 0004）；worktree 列表与提交模板是只读查询（不经过 Gate、不持写锁），创建要求分支未被任何 worktree 检出、目标为绝对路径且不存在或为空目录，移除只接受非主且未锁定的条目、绝不 `--force`（ADR-0034）。

**implementation**：Git CLI adapter、`--git-path`、porcelain v2 解析、`git add -A` / `git restore --staged` / unborn HEAD 的 `git rm --cached`、staged/client diff 生成（`--ignore-all-space` 只插入展示命令，hunk 写路径的 `tracked_diff_args` 不变，ADR-0030）、hunk 拆分与 `git apply` 补丁重建、Gate 的 warning/受影响路径报告（清单上限 50）、分支切换 stderr 诊断与恢复横幅信息；配置 `--list --show-scope` 解析与 `--replace-all` / `--unset-all` 写入、HOME 注入定位用户级文件（`src/config.rs`，原 app 层 gitconfig 下沉）；worktree porcelain 解析（缺字段按缺省、单条异常跳过）与提交模板读取（相对路径按仓库根解析、≤ 64 KiB、非法 UTF-8 lossy、超限/缺失返回 None，内容不写日志），创建/移除以参数数组启动、路径置末位（ADR-0034）。

### RefreshCoordinator

**职责**：合并文件监听、手动刷新和写操作触发的刷新请求，维护 generation 并丢弃过期结果（不提供刷新任务取消，见需求 F1）。

**interface**：`request(reason)`、`current_generation()`、`accept(result_generation)`。

**不变量**：监听事件只标脏；只有最新 generation 的结果可提交 UI；同一仓库同一时刻最多一个写操作。

### RepoRegistry（多仓库会话）

**职责**：把「同一窗口已打开的仓库」收拢为注册表：每个仓库一条会话（gix 读取、写互斥、`RefreshCoordinator`、文件监听、PTY 会话），命令按 `RepoId` 路由，前端标签栏只展示与激活（ADR-0032）。

**interface**：`open_repository(path)`（已打开则激活，不再新建会话）、`restore_repositories(paths, active)`（启动恢复：一次登记全部标签，只有活动仓库读状态，ADR-0036）、`list_repositories()`、`activate_repository(repo_id)`、`close_repository(repo_id?)`；Rust 内部 `entry_or_active(repo_id)` 为不显式带仓库的读写命令解析目标会话，兼容单仓库调用方。

**不变量**：标签数不设上限（ADR-0036）；每个仓库独立 generation 与写互斥（跨仓可并行、同仓仍串行）；watcher 只覆盖活动仓库与最近激活的 `WATCH_POOL_LIMIT = 8` 个，活动仓库必定在池内，切换一律重读状态并以返回的 generation 为准（正确性不依赖监听），PTY 会话按 `RepoId` 归属、关闭标签同批回收；`RepositoryChangedDto` 带 `repo_id`，前端只把事件应用到对应标签；设置中的 `open_repositories` / `active_repository` 保存标签列表与活动项，启动恢复经 `restore_repositories` 一次完成，缺失或打不开时记入 `failures` 并跳过该项；关闭最后一个标签回到欢迎页。

**implementation**：`state/{mod,registry,tabs}`（`AppState` 持有 `RwLock<HashMap<RepoId, Arc<RepoEntry>>>` 与活动 id，`registry` 记录 `last_active` 戳记，`tabs` 负责打开/激活/关闭、启动恢复与持久化，`mod` 的 `sync_watcher_pool` 统一按最近激活启停监听）；`watch.rs` 每仓库一个监听器，事件携带 `repo_id` 与各自的 generation；`terminal.rs` 的 PTY 会话记录 `repo_id` 并提供 `close_for_repo`；前端 `RepoTabBar` + `useRepoTabs` / `useRepoTabState`（每标签 UI 快照）与 `useTabController`（切换、关闭、终端保活），终端面板在标签切走后保持挂载仅隐藏，切回时 xterm 缓冲与 PTY 均原样保留。

### TerminalHost

**职责**：把 PTY 会话、子进程生命周期与 LazyGit/Shell 启动细节封装为受限命令。

**interface**：`capabilities()`、`open(mode, cols, rows, channel)`、`write(id, data)`、`resize(id, cols, rows)`、`close(id)`。

**不变量**：模式只接受 `lazygit` / `shell`；工作目录只能取当前仓库会话，前端不能传路径或任意命令；PTY 与子进程只由 Rust 创建和回收；日志只记录模式、仓库与退出码，不记录终端输出；进程退出后复用该仓库的 RefreshCoordinator 并发出带 `repo_id` 的仓库变更事件；切换标签保留 PTY（仅隐藏面板），关闭标签只结束该仓库的会话，关闭窗口时结束全部会话（ADR-0032）。

**implementation**：portable-pty（Windows ConPTY）、xterm.js 仅负责渲染与按键、base64 传输二进制输出、退出码用独立线程轮询（ConPTY 不保证 reader 及时 EOF）。

### 外观、设置与反馈

**职责**：在不扩大跨进程能力的前提下提供系统主题、全局缩放和版本/反馈入口。

**interface**：`load_settings()` / `save_settings(settings)` 读写 `SettingsDto`；`set_language(language)` / `set_shell_profile(profile)` 即时切换并独立持久化单项；`app_info()` 返回版本、平台与 Git 版本；`open_feedback_issue(title, body)` 只打开由应用构造的固定 Issue 页面。

**不变量**：窗口不强制 `Dark`/`Light`，由系统主题决定；主题只通过 CSS 语义令牌切换，不在组件内写死浅/深两套颜色；缩放使用 WebView `setZoom`，档位与范围受前端映射和 Rust 校验双重约束；`font_scale` 缺省 1.0，旧配置靠 serde 默认值迁移；反馈预填只含版本、系统与 Git 信息，不含日志、仓库路径或 Git 远端；打开浏览器必须由用户显式点击，且 URL 只能指向应用仓库的 Issue 页面。

**implementation**：`tokens.css` 深/浅色令牌与 `forced-colors` 规则；`App.tsx` 捕获缩放快捷键并持久化；`SettingsDialog` 的外观与关于区、反馈弹框；Rust `config` 模块校验 `font_scale`，`commands` 构造 Issue URL 并以参数数组启动系统浏览器。

## 数据流与 Tauri seam

1. 前端只请求分页摘要、指定提交详情或单文件 diff，不请求完整仓库历史。
2. Tauri command 层是唯一跨进程 seam：参数使用受限 DTO，返回 `Result<Dto, UserVisibleError>`。
3. Rust 内部错误映射为稳定错误码与中文提示；原始 stderr 只在诊断详情中显示。
4. 前端依据 `generation` 忽略旧响应；虚拟化只作用于已经取回的行。

## 状态模型

```text
StagingFile       = Staged | Unstaged | Conflicted | Untracked
```

仓库会话、写流程与对比双槽不设独立的业务状态机：generation（u64）与刷新协调由 `src-tauri/src/app/state/` 的 `RepoRegistry`（每仓库一条 `RepoEntry` 会话 + `RefreshCoordinator`，ADR-0032）承担，前端状态见 `useRepositorySession` / `useWriteFlow` / `useRepoTabState`（每标签 UI 快照），对比双槽是固定解析后 OID 或 `worktree` 保留字的前端状态（ADR-0030）。中断态（`CHERRY_PICK_HEAD` / `REVERT_HEAD`）优先于普通写操作入口；`Conflicted` 时只允许只读刷新与冲突解决三件套（ADR-0033），其余写操作入口保持关闭。分支移动、外部终端操作或文件监听事件都会请求新 generation，而不直接篡改 UI 数据。


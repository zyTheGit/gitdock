# GitDock 技术架构

## 架构原则

系统以 GitReadModule / GraphLayoutModule / GitWriteModule / RefreshCoordinator 四个核心深模块组织，另有 TerminalHost 与外观设置两个受限能力模块。每个模块只暴露调用方真正需要的 interface，把 Git 格式、并发、布局和进程细节留在 implementation 内，确保调用方获得足够 leverage，变更也集中在同一处保持 locality。

```text
React / Tauri WebView
  WorkspaceController ────────> GitReadModule ──> gix
         │                            │
         │                            └──> GraphLayoutModule
         │
         ├──────────────────────> GitWriteModule ──> Git CLI
         │                                  │
         └──────────────────────> RefreshCoordinator
```

## 模块与 interface

### GitReadModule

**职责**：将仓库、refs、对象格式、遍历与 diff 的复杂性封装为只读 DTO。

**interface**：`open_repository(path)`、`read_graph_page(query, cursor, limit)`、`read_commit(oid)`、`compare(base_oid, compare_oid)`、`search(query, scope, cursor)`、`export_tree(oid, sink)`。

**不变量**：所有 OID 使用仓库自身对象格式；页面按拓扑序；cursor 是不透明 continuation token，不允许 offset；返回值包含读取时的 repository generation。

**implementation**：gix 读取、ref peel、commit walk、diff 元数据与二进制降级、目录树导出（`TreeSink` 回调，落盘由 app 层 `dir_diff` 承担，ADR-0025）。这里是唯一了解 Git 对象结构的模块。

### GraphLayoutModule

**职责**：把按拓扑序的 `GraphPage` 映射为稳定 lane、边和待连接边。

**interface**：`append(page)` 返回可渲染增量，`reset(view_key)` 建立独立布局状态。

**不变量**：同一 `view_key` 生命周期内既有提交 lane 不改变；缺失父节点使用 pending edge；布局计算不访问文件系统、不执行 Git。

**implementation**：轨道分配、父子边路径、可视窗口裁剪。它是纯函数核心，适合由其他智能体独立验证。

### GitWriteModule

**职责**：把有限写操作封装为显式状态机，而非向前端暴露通用命令执行；Git 配置读写（白名单键、用户级/项目级两层）也经由本模块收敛，app 层不设第三个 Git 交互入口。

**interface**：`validate(operation)`、`execute(operation)`、`inspect_interruption()`、`staging_status()`、`staging_file_diff(path, staged)`、`read_git_config(repo)`、`save_git_config(scope, repo, entries)`。

**不变量**：仅接受白名单操作；命令以参数数组启动；每次执行前运行 Gate；每次非零退出后重新读取操作态；绝不自动 abort / quit；切换分支绝不自动 stash / reset / clean，dirty 时 Gate 返回不阻断的 warning 与受影响路径，由 `git switch --no-guess` 判定覆盖风险；暂存操作只接受当前 `git status` 中存在的路径，不做部分行暂存；暂存与 diff 的读取使用 `GIT_OPTIONAL_LOCKS=0`，避免监听自激；配置读写只开放白名单键且值经校验（控制字符/长度/邮箱/分支名字符集），项目级（`--local`）配置写与其他写操作共用同一互斥锁，用户级配置写不触碰仓库、无需持锁（见 ADR 0004）。

**implementation**：Git CLI adapter、`--git-path`、porcelain v2 解析、`git add -A` / `git restore --staged` / unborn HEAD 的 `git rm --cached`、staged/client diff 生成、Gate 的 warning/受影响路径报告（清单上限 50）、分支切换 stderr 诊断与恢复横幅信息；配置 `--list --show-scope` 解析与 `--replace-all` / `--unset-all` 写入、HOME 注入定位用户级文件（`src/config.rs`，原 app 层 gitconfig 下沉）。

**写操作白名单（`WriteKind` 共 27 项，`crates/git-core/src/dto.rs`；标签远程删除见 ADR-0022 §7）**：

| 域 | WriteKind | 命令形态 / 约束 | 决策 |
|---|---|---|---|
| 图谱操作 | `cherry_pick`、`revert` | 单提交；merge commit 需指定父（`-m`）；Gate 要求工作区干净 | F7、ADR-0001 |
| 中断收尾 | `continue_operation`、`abort_operation` | 只由用户确认触发；成功须同时满足退出码 0 与对应标记消失 | ADR-0001、ADR-0011 |
| 分支切换 | `switch_branch` | `git switch --no-guess`；dirty 时 warning 放行，由 Git 判定覆盖风险 | F8、ADR-0002 |
| 分支描述 | `set_branch_description` | `git config --local branch.<name>.description` | F5 |
| 暂存区 | `stage_files`、`unstage_files` | 只接受当前 status 中存在的路径，不做部分行暂存 | ADR-0002 |
| 提交 | `create_commit`、`amend_commit` | 消息写临时文件后 `--file`；amend 前历史改写确认 | ADR-0007 |
| 分支 | `create_branch`、`delete_branch`、`delete_branch_remote`、`rename_branch` | 删除仅 `-d`；远程删除先本地后 `push origin --delete` | ADR-0008、ADR-0022 |
| 标签 | `create_tag`、`delete_tag`、`delete_tag_remote`、`set_tag_description` | 描述 = 附注标签 message，目标统一 `^{commit}` peel；远程删除先本地后 `push origin --delete <tag>` | ADR-0008、ADR-0022、ADR-0024 |
| stash | `stash_save`、`stash_apply`、`stash_pop`、`stash_drop` | 仅手动，不自动 stash | ADR-0009 |
| 远程 | `fetch`、`pull`、`push` | pull 支持 `ff_only` / `merge` / `rebase`；push 不 force、不推 tags | ADR-0010、ADR-0011 |
| 历史整合 | `merge`、`rebase` | merge `--no-edit`；批量 pick 走序列，不自动 skip | ADR-0011 |

**模块划分（`crates/git-write/src`）**：

| 模块 | 职责 |
|---|---|
| `command.rs` | 白名单到参数数组的命令构造；不拼接 shell 字符串 |
| `gate.rs` / `commit/gate.rs`、`branch/gate.rs`、`tag/gate.rs`、`stash/gate.rs`、`remote/gate.rs`、`history/gate.rs` | 写前 Gate 分派与各域校验（工作区、中断态、上游、分支占用等） |
| `execute.rs` | 单请求单命令执行、退出码与操作态判定入口；`GIT_EDITOR` / `GIT_SEQUENCE_EDITOR` 固定为 `true` |
| `branch.rs` / `tag.rs` | 本地分支创建/删除/重命名、标签创建/删除/描述重写 |
| `commit.rs` | 提交创建与 amend、消息临时文件、提交前 Gate |
| `stash.rs` | 手动 stash save / apply / pop / drop |
| `remote.rs` | fetch / pull / push 与 `remote/failure.rs` 的认证、远端拒绝分类 |
| `history.rs` | merge / rebase / 批量序列与 `PullMode` |
| `interruption_outcome.rs` | 继续/中止的结果判定与文案（不自动收尾） |
| `staging.rs` / `status.rs` | stage/unstage 与 porcelain v2 工作区状态解析 |
| `description.rs` | 分支描述读写 |
| `config.rs`（含 `config/values.rs`） | Git 配置白名单键、两层作用域、HOME 注入、项目级写互斥 |
| `probe.rs` | HEAD / refs / worktree / 中断态只读探测 |

### RefreshCoordinator

**职责**：合并文件监听、手动刷新和写操作触发的刷新请求，维护 generation 并丢弃过期结果（不提供刷新任务取消，见需求 F1）。

**interface**：`request(reason)`、`current_generation()`、`accept(result_generation)`。

**不变量**：监听事件只标脏；只有最新 generation 的结果可提交 UI；同一仓库同一时刻最多一个写操作。

### TerminalHost

**职责**：把 PTY 会话、子进程生命周期与 LazyGit/Shell 启动细节封装为受限命令。

**interface**：`capabilities()`、`open(mode, cols, rows, channel)`、`write(id, data)`、`resize(id, cols, rows)`、`close(id)`。

**不变量**：模式只接受 `lazygit` / `shell`；工作目录只能取当前仓库会话，前端不能传路径或任意命令；PTY 与子进程只由 Rust 创建和回收；日志只记录模式、仓库与退出码，不记录终端输出；进程退出后复用 RefreshCoordinator 并发出仓库变更事件；切换仓库、关闭窗口时结束全部会话。

**implementation**：portable-pty（Windows ConPTY）、xterm.js 仅负责渲染与按键、base64 传输二进制输出、退出码用独立线程轮询（ConPTY 不保证 reader 及时 EOF）。

### 外观、设置与反馈

**职责**：在不扩大跨进程能力的前提下提供系统主题、全局缩放和版本/反馈入口。

**interface**：`load_settings()` / `save_settings(settings)` 读写 `SettingsDto`；`set_language(language)` / `set_shell_profile(profile)` 即时切换并独立持久化单项；`app_info()` 返回版本、平台与 Git 版本；`open_feedback_issue(title, body)` 只打开由应用构造的固定 Issue 页面。

**不变量**：窗口不强制 `Dark`/`Light`，由系统主题决定；主题只通过 CSS 语义令牌切换，不在组件内写死浅/深两套颜色；缩放使用 WebView `setZoom`，档位与范围受前端映射和 Rust 校验双重约束；`font_scale` 缺省 1.0，旧配置靠 serde 默认值迁移；反馈预填只含版本、系统与 Git 信息，不含日志、仓库路径或 Git 远端；打开浏览器必须由用户显式点击，且 URL 只能指向应用仓库的 Issue 页面。

**implementation**：`tokens.css` 深/浅色令牌与 `forced-colors` 规则；`App.tsx` 捕获缩放快捷键并持久化；`SettingsDialog` 的外观与关于区、反馈弹框；Rust `config` 模块校验 `font_scale`，`commands` 构造 Issue URL 并以参数数组启动系统浏览器。

## 数据流与 Tauri seam

1. 前端只请求分页摘要、指定提交详情或单文件 diff，不请求完整仓库历史。
2. Tauri command 层是唯一跨进程 seam：参数使用受限 DTO，返回 `Result<Dto, UserVisibleError>`。
3. Rust 内部错误映射为稳定错误码与中文提示；原始 stderr 只在诊断详情中显示。
4. 前端依据 `generation` 忽略旧响应；虚拟化只作用于已经取回的行。

## 状态模型

```text
StagingFile       = Staged | Unstaged | Conflicted | Untracked
```

仓库会话、写流程与对比双槽不设独立的 Rust 状态类型：generation（u64）与刷新协调由 `src-tauri/src/app/state.rs` 的会话和 `RefreshCoordinator` 承担，前端状态见 `useRepositorySession` / `useWriteFlow`，对比双槽是固定解析后 OID 的前端状态。中断态（`CHERRY_PICK_HEAD` / `REVERT_HEAD`）优先于普通写操作入口；`Conflicted` 时只允许只读刷新与展示终端接管信息。分支移动、外部终端操作或文件监听事件都会请求新 generation，而不直接篡改 UI 数据。

```text

  commands/{mod,repo,read,write,terminal,settings,gitlog,app}.rs   # 全部 IPC command 按域拆分

  config/{mod,tools,recent}.rs   # settings.json、工具探测、最近仓库
  menu.rs              # 应用菜单（macOS 设置入口，ADR-0012）
  platform/            # 平台适配层（paths / tools / url / shell，ADR-0005）
  terminal.rs gitlog.rs external.rs dir_diff.rs watch.rs logging.rs
crates/
  git-core/            # OID、DTO、错误码、cursor、状态模型（原 domain）；interruption / diff_limit / language / process 为跨 crate 共享内核
  git-read/            # GitReadModule 及 gix adapter
    src/read/{mod,graph,detail,compare,refs,probe,stash,message,export}.rs
    src/{search,diff,index,util}.rs
  graph-layout/        # GraphLayoutModule，纯函数
  git-write/           # GitWriteModule 及 CLI adapter
    src/{branch,tag,stash,remote,history,commit,staging,status,description,probe,interruption_outcome}.rs
    src/config.rs      # Git 配置读写：白名单键、两层作用域、HOME 注入与项目级写互斥

  fixture-gen/         # 夹具生成（fast-import 造大仓库），仅测试与基准使用
src/
  App.tsx              # 主界面装配（视图状态、菜单接线、Esc 分级退出）
  app/                 # 会话/分栏/写流程 hooks 与外壳组件
  features/graph/      # 图谱、虚拟列表、悬浮卡与 ref 标签
  features/detail/     # 提交详情、文件 diff 与语法高亮

  features/repository/ # 仓库切换、分支/标签对话框与右键菜单
  features/write/      # 写确认框、分支/标签描述、结果文案（原 operations）
```

前端 feature 不得直接了解 Git 命令、`.git` 路径或 Git 对象解析细节。

## 0. 快速开始

```bash
# 安装依赖
npm install

# 全量 Rust 测试（首次会自动生成夹具，约 10–60 秒）
cargo test --workspace

# 前端类型检查 + 构建
npm run build

# 开发运行
npm run tauri dev

# 带仓库路径启动（启动传参优先于“恢复上次仓库”）
npm run tauri dev -- -- -- "C:/path/to/repo"
```

首次接手建议阅读顺序：本文件 → `需求文档.md` → `docs/01-需求冻结.md` → `docs/03-技术架构.md` → `docs/04-任务拆分.md`。

`README.md` 面向终端用户（功能、支持环境、下载安装）；项目概览、环境前置与常用命令见 `docs/07-开发者指南.md`，本文件第 7 节保留开发/调试/夹具/运行期路径的细节。Node >= 24、npm >= 11 已写入 `package.json` 的 `engines`，并用 `packageManager: npm@11.16.0` 锁定 npm，与 CI 的 Node 24 一致。

  - 安全边界：`check_for_update` 无参数，请求地址只能来自 `update.rs` 的常量，因此它不会被前端当成通用 HTTP 代理；`open_release_page` **接受界面回传的字符串**，所以在 Rust 侧又校验一次前缀 `https://github.com/zyTheGit/gitdock/releases/`（前缀含协议与主机名，`http://`、`file:///`、`github.com.evil.test`、改名前的 `zyTheGit/git-graph` 一律拒绝），检查响应里的 `html_url` 也是先校验后才返回。也就是说它不是“打开任意 URL”的出口，后续若放宽前缀或改成资产直链下载，等同于扩大这个命令的能力面，需重新评估。`update.rs` 内 11 项单元测试覆盖纯解析分支（端点常量、新/同/旧版本、prerelease、两位数比较、非 semver 标签、非 JSON 响应、站外地址、打开页前缀白名单）与 TLS provider 配置。
  - 前提：仓库 `zyTheGit/gitdock` **必须是 public**。private 时 GitHub Releases API 对未登录请求返回 404，界面只会显示“检查更新未成功”（`ErrorCode::Io`，“无法获取最新版本信息”），方案 B 整体失效。未认证限额为每 IP 60 次/小时，相对每用户 24 h 一次的节流没有压力。
  - 实机核查（2026-11-02，debug 构建 + CDP）：真实请求返回 **404**（仓库仍为 private），界面文案为「版本信息接口返回状态 404」；同一 IP 触发匿名限额时 GitHub 返回 **403**，两种状态码都归 `ErrorCode::Io` 并附可能成因。`available` 分支是把端点临时指向 `BurntSushi/ripgrep` 后实测的（发现新版本 v15.2.0 → 跳过此版本 → 撤销跳过 → 打开下载页，状态栏「更新」标记同步出现/消失；重载页面后 24 h 内不再自动检查），验证后端点常量已还原。**教训**：ureq 的 TLS provider 不会因为编入了 `native-tls` 就自动启用，provider 仍是默认的 rustls，https 请求会在连接阶段 **panic**（“uri scheme is https, provider is Rustls but feature is not enabled”），被 `spawn_blocking` 包成「内部错误：后台任务异常」——`cargo build`、`clippy` 与全部单元测试（都是纯解析、不触网）都发现不了它。`https_config()` 必须显式 `TlsProvider::NativeTls` + `RootCerts::PlatformVerifier`，`update.rs` 里已加一条不触网的回归用例守住这两个值。
  - store 语义：检查失败时只翻转 `status` 为 `failed`，**保留上一次成功的 `result`**——一次网络抖动不该让已经发现的更新消失，而下一次自动检查还要等 24 h。两处 UI 都以 `pendingUpdate(state)` 为唯一判断，不各自解读 `available`。
  - 方案 A（minisign 自动更新）本轮明确**延期，不做**：它要引入下载、安装与失败回滚路径。注意 minisign 更新签名**不等于** Authenticode 代码签名，因此方案 A 并不依赖仍未到手的签名证书（第 10 节第 6 条），两者是各自独立的决策；真要升级到 `latest.json` + 安装包直链时先走 ADR。

## 3. 技术栈与硬约束

- Tauri 2 + React 18 + TypeScript 5.6 + Vite 5；Rust stable（workspace `rust-version = 1.85`）。
- 读取：gix（只读）。所有写操作与状态查询：Git CLI，**参数数组、不经 shell**。
- 图谱布局、稳定 lane、写前 Gate、写操作状态机全部自研。
- 前端不得执行任意命令、拼接 shell、读取 `.git` 内部路径或解析 Git 对象，只能调用注册过的 Tauri command。
- Git 状态路径一律通过 `git rev-parse --git-path <name>` 取得（兼容 linked worktree）。
- OID 同时支持 SHA-1（40 位）与 SHA-256（64 位），不得假设固定长度。
- 不得复制 VS Code Git Graph / GitButler 的代码、资源、样式与测试夹具。

## 5. 数据流与状态

1. **打开仓库**：`open_repository` → 校验路径 → 新建 gix 只读会话 + 监听器 → 返回 `RepoStateDto`（含随机 `generation`）→ 前端重置范围/选中/过滤并写回最近仓库。
2. **读取图谱**：`read_graph_page(generation, cursor)` → `cursor` 为 opaque token（禁止 offset）→ 返回 `GraphPageDto` → 前端布局并渲染。旧 generation 的结果不得覆盖新 UI。
3. **刷新**：监听器只负责“标脏 + 防抖”；刷新经 `RefreshCoordinator` 合并，完成后仅最新 generation 生效；前端 `repository-changed` 后带 `keepRows` 重载。
4. **写操作**：`validate_write`（Gate）→ 确认框 → `execute_write`（全局互斥）→ 以退出码 + 执行后探测的 `CHERRY_PICK_HEAD` / `REVERT_HEAD` 判定：成功 / 冲突横幅 / 普通失败；绝不解析 stderr 猜冲突，绝不自动 abort/quit。
5. **对比槽**：填入时固定解析后的 OID；HEAD 或分支移动不改变已固定的对比结果；第三次 Ctrl+点击弹“替换哪一侧”。顶部“对比”按钮或侧栏“对比分支…”可打开分支对比弹窗，按本地分支两两选择。对比视图默认三点 diff；可切换两点快照（`git diff base compare`）查看两端完整差异；三点结果为空时解释原因（Compare 为 Base 祖先或两端工作树一致），同一提交则单独提示。
6. **终端**：前端 `terminal_open(mode, cols, rows, channel)` 只传模式与尺寸；Rust 从当前会话取仓库路径作为 cwd，ConPTY 输出经 `tauri::ipc::Channel` 以 base64 推回；退出由 waiter 线程轮询 `try_wait` 后发 Exit 事件并请求 `RefreshCoordinator`（`Watch`），前端收到 `repository-changed` 后按既有流程刷新。收起面板只隐藏、不结束进程；关闭会话、切仓库或退出应用才结束进程。日志只记录模式、仓库与退出码，不记录终端输出。

## 6. 关键不变量（改代码前必读）

1. 读取只读；任何改工作区/index/refs 的动作只走 Git CLI。
2. 写前 Gate：工作区干净、无中断态、无 `index.lock`、非 detached HEAD、非 merge commit。
3. 状态路径用 `git rev-parse --git-path`，禁止拼 `.git/`。
4. cursor 必须是 opaque token，禁止 offset。
5. 同一 view_key 生命周期内，已渲染提交的 lane 不得变化；跨页父边保持“待连接”。
6. 所有异步结果携带 repository generation；旧 generation 不得覆盖新状态。
7. OID 支持 40/64 位；复制时使用完整 OID。
8. 外部工具仅“可执行文件 + 参数数组”，路径原样单参数传递。
9. 启动时检测 Git 版本；低于 `MINIMUM_GIT_VERSION`（当前 `2.30.0`，见 `crates/git-read/src/read/probe.rs`）时只读可用、写操作禁用。
10. 默认每页 200 条（上限 500），见 `DEFAULT_PAGE_LIMIT` / `MAX_PAGE_LIMIT`。
11. 只读子命令走 `run_readonly`（`GIT_OPTIONAL_LOCKS=0`）：`git status` 默认会创建/删除 `index.lock`，被监听器当成元数据变化，会形成刷新自激循环；该变量不得用于写操作。
12. 终端命令不得接收工作目录；cwd 只能来自当前仓库会话。前端不得直接 spawn 进程或访问 PTY。
13. 终端只能以 `lazygit` / `shell` 模式启动；LazyGit 配置路径失效时不回退 PATH（避免“配置了却运行了另一个”），并在界面提示。
14. 日志不得写入终端输出；只记录模式、仓库路径（由 Rust 提供）与退出码。
15. 收起面板 ≠ 结束进程；结束会话只在关闭会话、切仓库、退出应用时发生。切仓库后前端收起面板并提示，避免误以为旧会话仍在。

## 10. 已知限制与风险

1. 文件监听只覆盖 Git 目录：单纯编辑工作区文件不会立即更新“脏”徽标，需下一次 Git 事件或手动刷新。
2. `branches_containing` 对每个本地分支各自遍历祖先，超大仓库 + 多分支时开销偏高。
3. 设置中切换 `watch_enabled` 会重启监听，但不强制立即刷新一次，靠下一次事件补齐。
4. F1-1 后端首屏已实测 504 ms（5 万提交，release）；前端首帧渲染与 10 万提交内存占用尚未测量。
5. oid→parents 缓存随 generation 重建；refs 极活跃的大仓库命中率低，可考虑增量索引。
6. Release 打包已验证（`6ad6339`：MSI 5.00 MiB / NSIS 3.46 MiB），但**未签名**。2026-11-02 核查本机无可用代码签名证书（详见 8.2），签名需先获得外部证书，可选路径：① **Azure 可信签名**（Trusted Signing，按量付费，Tauri 2 原生支持 `bundle.windows.trustedSigning`，个人开发者需通过身份与历史校验）；② **CA 购买的 OV/EV 证书**（2023-06 起 CA/B 论坛要求私钥存于硬件令牌或云 HSM，需配 `certificateThumbprint` + 时间戳服务器）；③ **SignPath**（开源项目可免费申请，需公开仓库与流水线协作）。自签证书只能消除本机告警，对分发无意义，不作为方案。
7. Windows 下运行中的 exe 会锁产物，需要先停 dev 再构建。
8. Windows GUI 进程启动 `git` 必须带 `CREATE_NO_WINDOW`，否则每次子进程会被默认终端接管、耗时约 3 s（release 冷启动曾因此延迟约 30 s，已修复）。
9. 对比仍是“两端”模型：支持用户切换三点/两点、分支右键两两对比与分支对比弹窗；3+ ref 同时对比仍未实现。
10. 分栏宽度保存在 WebView 的 `localStorage`，不写入 `settings.json`；清除站点数据后恢复默认宽度。
11. 悬浮卡=行内元数据+`commit_branch_context` 分支摘要；分支摘要按提交缓存，命中后不再查询。它只统计本地分支（不含 remote/tag），最多比较 6 个分支、每个方向列 2 条提交，不展开文件差异；完整的 3+ ref 两两对比仍属 P1。
12. diff 的“放大”仍是单文件临时视图，不会脱离当前 Base/Compare 或提交上下文；放大期间用左侧文件列表切换，文件行右键可调用外部对比工具；收起状态与“换行”偏好都写入 `localStorage`（`git-graph.diff-files-open` / `git-graph.diff-wrap`），不写入 `settings.json`；字号固定 14px，暂无调节入口。并排且不换行时（放大视图、提交详情、对比视图）均为自绘等宽分栏：整体不出现横向滚动，长行在各栏内横向滚动、左右与上下滚动同步，较窄一侧到上限后较宽一侧可继续滚动；开启“换行”会退回整宽折行表格。
13. 最近仓库不设条数上限，只保存路径与时间戳、不扫描磁盘，因此列表过长只会让 `settings.json` 线性增大（每条约 100 字节），靠下拉框内的搜索与滚动控制；下拉里的“×”只移除展示项，不删除磁盘仓库，没有二次确认，也不提供撤销（再次打开该仓库即可回到列表）。允许删到最后一条：当前仓库始终以“当前窗口”保留且不可删除，最近列表清空后下拉只剩该项并给出空态提示。
14. 内置工具探测只覆盖 Windows 常见安装路径（`%LOCALAPPDATA%\Programs`、`%ProgramFiles%`、`%ProgramFiles(x86)%` 下的 VS Code / Zed / Beyond Compare）；便携版、自定义目录或非 Windows 平台需在设置中手动新增。
15. 搜索是逐页扫描而非全库建索引：消息/作者/hash 前缀每页最多检查 20000 个提交，路径匹配只检查前 2000 个提交（`MAX_PATH_SCAN`），超出部分的路径不参与匹配，结果里也不提示“路径未扫完”。
16. 搜索候选只覆盖当前已加载的图谱页（默认 200 条）：未加载的提交、分支名、文件路径不会出现在候选里，也不做后台补全；候选不保存历史，输入为空时下拉为空。
17. 状态查询已加 `GIT_OPTIONAL_LOCKS=0`，本应用自身不再创建 `index.lock`；但外部编辑器或终端里的 Git 命令仍会瞬时创建并删除 `index.lock`（监听器视为元数据变化），外部高频 Git 操作期间仍可能多刷新一次，属预期行为，不做抑制。
18. 终端面板高度保存在 WebView 的 `localStorage`（`gitdock.terminal.height`），不写入 `settings.json`；清除站点数据后恢复默认高度。面板是否展开不持久化，每次启动收起。
19. 终端以当前用户权限运行，未做沙箱或命令过滤；约束只有“cwd 取当前仓库 + 模式仅 LazyGit/Shell”。中文输入法仅做了窗口级检查，真实 IME 候选窗定位与多屏 DPI 变化后的 resize 尚未逐项实测。
20. 终端输出经 base64 事件流推给 xterm，未做背压/截断/日志落盘；极高吞吐命令的内存占用由 xterm 缓冲与 WebView 承受。LazyGit 路径留空时从 PATH 查找；填了但失效时不回退 PATH，只在界面提示。
21. 主题默认跟随系统，设置的外观分区提供应用内覆盖（跟随 Windows / 浅色 / 深色，存 `localStorage` 的 `gitdock.theme`；覆盖存在时系统切换不生效）。真实 Windows 深色模式切换已于 2026-11-02 在 release 上验证（双向实时生效、无需重启，见 8.2）；高对比度主题仍只有 CDP `forced-colors` 仿真证据，多显示器 DPI 组合因本机单屏未验证。终端内容固定深色 ANSI 配色。
22. 缩放为 WebView 整体比例（75%–200%），设置写入 `settings.json` 的 `font_scale`；连续按键的持久化有 300 ms 防抖，退出应用前 300 ms 内的最后一次调整可能不落盘。旧配置缺少 `font_scale` 时按 1.0 读取，不升级 schema。
23. 设置弹窗只保留 `.settings-body` 一条滚动条，工具列表随内容展开；工具或说明较多时“关于”区会被推得更远，需要继续滚动查看，不再有列表内滚动。
24. 窄视口（高缩放或窗口拖窄）下图谱按容器宽度依次隐藏日期、作者、哈希列，完整元数据仍可在悬浮卡查看；可视宽度 ≤640 px 时侧栏隐藏，641–900 px 收窄到 `min(220px, 25vw)`，暂无抽屉或浮动入口。详情窄于 520 px 时改为整块纵向滚动，diff 内部的横向/纵向滚动条会与外层滚动并存；≤900 px 时图谱与详情改为上下堆叠，图谱固定 320 px 高。
25. 继续/中止只接管“恰好一个”`CHERRY_PICK_HEAD` / `REVERT_HEAD` 的单次 cherry-pick / revert：出现 `sequencer`、`MERGE_HEAD`、rebase 目录或 `index.lock` 时 Gate 直接拒绝并提示终端，批量序列与 merge / rebase 中断仍无法在应用内收尾。继续时若结果为空，Git 会保留中断标记，应用只提示 `git cherry-pick --skip` / `git revert --skip`，不自动跳过；中止是不可撤销的破坏性操作，已手工解决的冲突内容不会备份。
26. merge commit 的 cherry-pick / revert 必须在确认框选择基线父（`-m N`，1 起始）；父提交说明读取失败时退回短 OID + 空说明，仍可执行。非 merge commit 携带 `mainline` 会被 Gate 拒绝，前端只对 `is_merge_commit` 的结果发送该字段。父列表只在 Gate 时读取一次，若期间提交被外部改写，执行时仍以 Git 自身校验为准。
27. 对比提交列表高度是组件内状态：默认 160 px、最小 96 px、最大为侧栏高度 70%，离开对比视图后回到默认值，不写入 `localStorage` / `settings.json`。
28. 夹具生成用 `target/test-fixtures/.fixtures-lock` 做跨进程互斥。若进程在持锁期间崩溃（Ctrl+C、调试器终止），锁文件会残留，后续测试等待 180 s 后报“等待其它测试进程生成夹具超时”，需手动删除该文件；`generate_all` 已能在半成品目录上重跑，但不会自动回收锁。

## 12. 常见坑

1. **新增 Tauri command 不生效**：先确认已加入 `src-tauri/src/lib.rs` 的 `generate_handler!`，然后重启 dev 应用。
2. **CDP 读不到结果**：脚本先打印 JSON 值、再打印 console 事件；用 `head` 查看，或直接 grep。页面未加载时先加 `--wait`。
3. **启动参数不生效**：必须用第二个 `--` 分隔（`tauri dev -- -- <appArgs>`）；经 npm 时是 `npm run tauri dev -- -- -- "<path>"`。第一个非选项参数生效。
4. **夹具生成慢或卡住**：检查是否残留 `.fixtures-lock` 与是否有并发测试；不要手工删除其他进程正在使用的夹具。
5. **测试环境 node 找不到**：本机用 fnm，需将 `.../fnm/node-versions/v24.18.0/installation` 加入 PATH。
6. **写操作误报冲突**：结果判定只能看退出码 + 重新探测中断态；禁止解析 stderr 文本。
7. **linked worktree**：任何 `.git` 路径都要经 `rev-parse --git-path`，不能用 `.git/xxx` 拼路径。
8. **`settings.json`**：有 `schema_version`，未知版本会被忽略/重置；不要随意改字段名。`tools_seeded` 为 `true` 后不再自动探测内置工具，用户清空列表属于预期行为，不要在启动时“补回”。
9. **release 下 git 子进程**：GUI 进程 spawn `git` 必须带 `CREATE_NO_WINDOW`；现已统一由 `git_core::process`（`git_command` / `hide_console`）提供，不要在模块内再手写，否则默认终端接管导致每次约 3 s。
10. **生产 CSP**：`connect-src` 必须包含 `ipc: http://ipc.localhost`，否则 release 的 IPC 会先失败再回退；`script-src` 必须包含 `'wasm-unsafe-eval'`，否则 Shiki 语法高亮在 release 中会因 WebAssembly 被拦截而静默退化为纯文本（dev 下容易漏测）。**`index.html` 里不要写内联 `<style>` / `<script>`**：Tauri 会因此给 `style-src` 追加 `nonce-…`，而 nonce 一旦存在 `'unsafe-inline'` 对 style 属性失效，React 的所有行内 `style` 被静默丢弃（dev 无 CSP，只有 release 复现，表现为虚拟列表行、并排 diff 双栏等布局塌陷为空）。
11. **Electron 外部工具“打开无反应”**：若父进程环境带 `ELECTRON_RUN_AS_NODE=1`（VS Code / 代理终端常见），VS Code、Zed 会按 Node 启动并立即退出；`external.rs` 启动前已 `env_remove`，从这类终端自测 release 时不必再手工清理。VS Code / Zed 的参数模板必须用 `--diff $LOCAL $REMOTE`，只写 `$LOCAL $REMOTE` 会打开两个独立文件而非 diff（Beyond Compare 相反，直接传两个路径）。
12. **源码明明有导出，`tauri build` 却报 unresolved import**：cargo 只按 mtime 判定依赖是否过期。若源文件在复制/回滚/时钟回拨后 mtime 早于 `target/release` 里的产物，cargo 会把 crate 判为 `Fresh`，继续链接重构前的旧 rlib；而 `cargo check` 因为没有旧产物会重新编译并通过，容易误判成代码问题。先看 `target/release/deps/<crate>-*.d` 是否缺少新模块，再用 `cargo clean -p <crate>` 或 touch 相关源文件后重建。
13. **≤900 px 上下堆叠**：`.workspace` 在窄窗口改为纵向排列时，`.graph-pane` 必须给定高度（当前 `flex: 0 0 320px`）。图谱是虚拟列表，内容高度可达数万像素，若用 `flex: none` 让高度自适应，会把详情面板顶出视野。恢复侧栏显示时用 `display: block`（侧栏默认块级），不要用 `flex`，否则仓库信息与分支列表会并排挤成两列。
